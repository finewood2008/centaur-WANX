# Builder 原生 Codex 调用与会话复用

Builder 的初始需求访谈、后续迭代分析和正式构建直接调用本机 Codex app-server。已有 ACP 引擎配置和历史会话 ID 兼容；项目、业务数据和版本结构不迁移。

## 实现

- 按用户、项目和角色隔离持久 Node worker，复用 Codex 进程、MCP 通道与 thread。独立迭代保留各自会话范围。
- 每轮重新绑定本轮冻结方案、契约、源码和工具授权。排队输入不能提前进入旧轮次。失败的模型请求不自动重发。
- 构建前只检查本机配置，不再启动并关闭另一套完整预检环境。显式环境检查仅验证原生连接，不创建临时 thread，不启动 MCP/CLI，不调用模型。
- 原版 CLI 在 turn/start 之后异步挂接同一会话，沿用稳定会话目录，避免后续任务目录触发“信任此文件夹”交互。终端慢或失败不阻止开发；短任务完成后也不等待完整终端超时。
- 空闲五分钟退出；之后恢复已保存 thread。配置变化、取消、断开、删除项目和服务关闭清理相应进程。

原有需求确认、结构化问题、连续消息队列、预览圈选、局部修改、固定编译、版本、验收、安装、只读终端和历史回放沿用原业务实现。每次工具调用继续检查当前用户、项目、引擎和资源授权。没有开放 Shell、任意文件工具或终端输入，不展示内部推理。只有模型 turn 完成并通过原有校验才提交成功版本。

## 验证

- 完整 Builder 回归：181 项 Node 与 192 项 Python 测试通过。最终修改再运行原生传输、进程清理、终端、连续消息和迭代相关回归。
- 真实合成访谈两轮：相同进程/thread；第二轮会话就绪约 1ms，首段文字约 4.5s。
- 真实合成构建两轮：第二轮仅将指定标题 A 改为 B，其他字节保持不变；相同进程/thread，两轮原版 CLI 均观察同一会话。第二轮会话就绪约 33ms，首段文字约 2.1s，第一工具约 3.2s。
- 完整 Runner 合成闭环：两轮成功交付并复用 worker，合成业务记录逐字保留。
- 已安装服务附带的旧 test_studio.py 有 6 项历史失败，涉及已移除的额度或旧接口断言；未修改版本和迁移候选的失败集合相同，没有计为通过。

时间来自合成验证，不是相同业务任务的严格前后对照。冷启动、模型推理和网络仍影响耗时；未更换用户模型或降低构建推理强度。

## 本机更新与回退

源代码与已安装服务分别以各自当前内容为基线，仅应用传输及生命周期修改，保留两者原有业务差异。客户端安装包、账号和业务数据库不被旧源码覆盖。

安装前保存完整 SQLite 快照及原服务文件，检查没有运行中的 Builder 任务。更新后重启本机服务并比对项目、版本、消息、记录及事件指纹。回退应恢复备份服务文件并重启；除非明确需要数据恢复，不覆盖当前数据库。

协议依据：[OpenAI 官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。

本机数据库备份实际保存在 ORICO 的验收目录，原 Application Support 备份路径保留符号链接；本次完整性校验和内容指纹比对均通过。更新期间曾遇到 launchd 注册延迟，重试后启动项恢复。

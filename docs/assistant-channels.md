# 助理通道设置

个人版和团队版的完整版助理提供微信、企业微信、飞书和钉钉通道管理。托盘 mini 保留简洁的聊天入口。正式助理的历史按钮位于标题左侧，历史栏默认展开；mini 的历史栏默认收起。

通道可扫码接入；企业微信、飞书和钉钉也支持手动填写已有机器人的配置。列表显示连接状态，支持编辑、检查、启停和确认后移除。扫码需要用户在相应平台确认授权，连接成功不代表已经完成真实消息收发验收。

连接绑定当前真实账号、盒子和私人助理专家。两版在同账号、同盒子下管理同一组通道。外部通道沿用原生会话路由与工具权限，网页对话临时选择的空间、知识库授权不复制到通道。切换账号或盒子会关闭设置、清空表单并作废尚未完成的本地扫码流程。

## 可信层边界

渲染层只调用固定的 `dialogue.channels-*` 操作，不指定专家 ID、任意 API 地址或代操作用户。主进程从 `/api/assistant/profile` 获取私人助理，再调用已有的 `/api/agents/{agent_id}/channels` 接口；后台继续校验账号权限和专家归属。mini 的 preload 和主进程操作白名单均不开放这些通道操作。

| 操作 | 用途 |
|---|---|
| list / detail | 返回四类通道摘要、非密钥配置及已配置密钥的字段名 |
| save / toggle / delete / test | 保存配置、启停、移除和检查连接 |
| start / poll / cancel | 发起、轮询或取消用户主动开始的扫码流程 |

已有密钥、原始配置、扫码 token 和创建过程日志保留在可信层。渲染层接收本地随机句柄及本机生成的二维码；二维码生成不依赖外部图片服务。编辑时留空的密钥保留原值，并合并最新原生配置。保存或关闭设置后清空输入框；迟到的扫码结果不能在取消、换账号或换盒子后创建连接。重复轮询和重新扫描同一机器人不会重复创建绑定。

实现与类型位于 `wanx-studio/integration/team-client/`。二维码组件与 MIT 许可证一起分发；`wanx-studio/tools/assemble-client.mjs` 将共享服务、二维码组件和通道图标复制到两版客户端。只给完整版管理窗口注册通道 IPC，保持原有账号、数据库、后台接口和权限体系。

## 验证范围

验证覆盖四种通道的合成扫码流程、密钥隔离、编辑保留密钥、启停、移除确认、轮询去重、取消和账号/盒子边界。两版隐藏 Electron 窗口验证历史默认状态、四类通道与图标、手动配置、移除确认、取消二维码、草稿保留、换账号清理、mini 无通道入口和窄屏布局。

真实平台扫码授权及外部消息收发仍需用户完成授权后验收。最新 Windows 安装包验收另行进行；源码测试中的平台或环境跳过项不视为通过。

# 对话通道设置

个人版和团队版的完整版对话提供微信、企业微信、飞书和钉钉通道管理。托盘 mini 保留简洁的聊天入口。正式对话的历史按钮位于标题左侧，历史栏默认展开；mini 的历史栏默认收起。

通道可扫码接入；企业微信、飞书和钉钉也支持手动填写已有机器人的配置。列表显示连接状态，支持编辑、检查、启停和确认后移除。扫码需要用户在相应平台确认授权，连接成功不代表已经完成真实消息收发验收。

连接绑定当前真实账号、盒子和私人通用专家专家。两版在同账号、同盒子下管理同一组通道。外部通道沿用原生会话路由与工具权限，网页对话临时选择的空间、知识库授权不复制到通道。切换账号或盒子会关闭设置、清空表单并作废尚未完成的本地扫码流程。

## 可信层边界

渲染层只调用固定的 `dialogue.channels-*` 操作，不指定专家 ID、任意 API 地址或代操作用户。主进程从 `/api/assistant/profile` 获取私人通用专家，再调用已有的 `/api/agents/{agent_id}/channels` 接口；后台继续校验账号权限和专家归属。mini 的 preload 和主进程操作白名单均不开放这些通道操作。

| 操作 | 用途 |
|---|---|
| list / detail | 返回四类通道摘要、非密钥配置及已配置密钥的字段名 |
| save / toggle / delete / test | 保存配置、启停、移除和检查连接 |
| start / poll / cancel | 发起、轮询或取消用户主动开始的扫码流程 |

已有密钥、原始配置、扫码 token 和创建过程日志保留在可信层。渲染层接收本地随机句柄及本机生成的二维码；二维码生成不依赖外部图片服务。编辑时留空的密钥保留原值，并合并最新原生配置。保存或关闭设置后清空输入框；迟到的扫码结果不能在取消、换账号或换盒子后创建连接。重复轮询和重新扫描同一机器人不会重复创建绑定。

实现与类型位于 `wanx-studio/integration/team-client/`。二维码组件与 MIT 许可证一起分发；`wanx-studio/tools/assemble-client.mjs` 将共享服务、二维码组件和通道图标复制到两版客户端。只给完整版管理窗口注册通道 IPC，保持原有账号、数据库、后台接口和权限体系。

## 验证范围

验证覆盖四种通道的合成扫码流程、密钥隔离、编辑保留密钥、启停、移除确认、轮询去重、取消和账号/盒子边界。两版隐藏 Electron 窗口验证历史默认状态、四类通道与图标、手动配置、移除确认、取消二维码、草稿保留、换账号清理、mini 无通道入口和窄屏布局。

真实平台扫码授权及外部消息收发仍需用户完成授权后验收。最新 Windows 安装包验收另行进行；源码测试中的平台或环境跳过项不视为通过。


## 本人确认与渠道历史

连接完成后，用户开始本人验证，在五分钟内用本人账号向机器人发送任意一条新的私聊。界面显示消息发送者和截断的预览，用户点击「确认是本人」后才完成绑定，不要求输入验证码。确认前的私聊不开放私人通用专家，群聊及其他访问者不能使用已绑定专家的上下文。通道凭据变化、账号停用或撤销验证后重新校验。

完整版历史列表合并同一账号、同一盒子、同一私人通用专家下的原生渠道会话，使用「客户端」「微信」「企业微信」「飞书」「钉钉」等来源标签；搜索也匹配来源。后台列表提供 `channel_type`，可信主进程在旧盒子上可从原生线程补齐来源，但不返回路由键、通道凭据或聊天对象标识。可见的完整版每十秒后台刷新历史列表，保留当前草稿、附件、模型及回答状态；mini 不启动此轮询。

删除的会话保持在回收站。新渠道消息不再继续写入已删除会话；旧客户端已经写入的删除后消息，只有可靠时间戳证明晚于删除时间时，才复制至唯一的新原生会话并重新绑定后续渠道消息。原消息、旧线程和删除状态保持不变，不触发模型生成或工具重放。并发刷新使用确定性后继线程和锁避免重复。


## 新对话资料选择

新对话继承最后一次手动设置的空间、星图开关与所选范围；旧对话继续保存各自的选择，打开历史不会改写新对话默认值。模板按账号、真实盒子和现有个人/团队资料上下文保存在后台，重开客户端后可恢复。保存模板不申请 MCP 授权，实际发送时重新校验权限并续期。不可用范围保留并报告具体原因，不静默扩大、替换或授权。无模板时保持默认关闭；旧盒子尚无该接口时安全回退。

# WANX 应用上架：安装包与产品素材交付要求

生效版本：素材规范 v1，2026-10-16。适用于新上架应用及后续提交的新发行版本。

应用上架交付物必须同时包含可安装制品、签名描述和产品素材。Logo、图标、真实产品截图、产品介绍海报与文案由应用提交方随发行包交付，不能由市场客户端临时采集用户电脑上的界面补齐。

## 必交清单

| 项目 | 要求 | 用途 |
| --- | --- | --- |
| 安装制品 | `.wanxapp` 及配套 `.wanxapp.release.json`，或市场支持登记的原生制品；沿用现有签名、版本与平台规则 | 安装、更新与完整性验证 |
| 应用图标 | 1 张，1024 × 1024 PNG，正方形、不预裁圆角，≤ 2 MB | 应用列表、详情页与快捷入口 |
| 产品 Logo | 1 张透明背景 PNG，长边至少 512 px，≤ 2 MB；可与图标使用同一品牌符号，但须提供适合明暗背景的独立素材 | 品牌标识与海报排版 |
| 真实产品截图 | 3–8 张 PNG/JPEG，横向画面至少 1280 × 720，单张 ≤ 5 MB | 版本审查、功能核对与后续市场展示 |
| 产品介绍海报 | 1–3 张 PNG/JPEG，推荐统一 3:2、至少 1536 × 1024，单张 ≤ 5 MB | 当前产品介绍页主视觉 |
| 产品介绍 | 产品名称、短介绍、完整介绍、3–6 个功能亮点、适用场景、使用条件、支持联系方式 | 应用介绍与审核 |
| 版本说明 | 与本次制品版本一致的更新说明、兼容性和权限／数据使用说明 | 更新决策与版本追溯 |
| 素材索引 | UTF-8 `marketplace/metadata.json`，对应应用 ID、版本、语言及全部素材相对路径，图片含说明与替代文本 | 素材交接与后续自动导入 |

素材合计建议不超过 30 MB；安装包仍受现有包大小限制。不要通过扩大海报数量或重复图片填充内容。应用图标和产品 Logo 不以海报中的小图替代。

## 包内目录

`.wanxapp` 输入构建目录应包含下列普通文件；路径使用相对于包根目录的路径，遵循现有路径安全规则。素材与应用代码一起进入已签名的完整制品，提交签名后不得替换包内图片。

```text
build/my-application/
  wanx-app.json
  main.mjs
  ...运行依赖与应用资源
  marketplace/
    metadata.json
    icon.png
    logo.png
    screenshots/
      01-overview.png
      02-workflow.png
      03-result.png
    posters/
      01-product.png
      02-feature.png          # 可选
      03-scenario.png         # 可选
```

素材索引是独立交付文件，不向运行时 `wanx-app.json` 擅自添加未支持字段。应用 ID 与版本必须和运行时清单及发行描述完全一致。原生安装器无法携带上述目录时，需同时提交同版本素材 ZIP；归档根目录仍为 `marketplace/`，审核记录关联该原生制品，不能只给会过期的外链。

下面是文件结构示例。提交时补齐 3–8 张截图、真实介绍、兼容条件与联系方式；示例内容不能原样用于正式上架。

```json
{
  "schemaVersion": 1,
  "applicationId": "example.application",
  "version": "1.0.0",
  "locale": "zh-CN",
  "name": "示例应用",
  "summary": "用一句话说明用户可以完成什么。",
  "description": "介绍目标用户、主要工作流程与结果。",
  "features": [
    { "title": "功能一", "description": "用户能完成的具体操作。" },
    { "title": "功能二", "description": "用户能查看或获得的结果。" },
    { "title": "功能三", "description": "用户能控制与确认的环节。" }
  ],
  "requirements": ["需要连接已授权的万象盒子"],
  "support": { "email": "support@example.com" },
  "icon": "marketplace/icon.png",
  "logo": "marketplace/logo.png",
  "screenshots": [
    { "file": "marketplace/screenshots/01-overview.png", "caption": "工作区总览", "alt": "应用主要操作区域与导航", "sampleData": true },
    { "file": "marketplace/screenshots/02-workflow.png", "caption": "主要操作流程", "alt": "执行关键操作时的真实界面", "sampleData": true },

```

图片路径不能包含绝对路径、上级跳转、符号链接或外部 URL。不得夹带用户数据、凭据、密钥、缓存及开发环境文件；所有图片和字体必须有合法使用权。

## 真实截图与海报分开验收

真实截图必须来自本次提交版本的实际可运行产品，至少覆盖工作区总览、核心流程、结果或管理状态。使用专门的演示账号和公开或合成数据，并标明示例内容。清除私人对话、文件名、电话号码、账号标识、余额、访问令牌与内部网址；不能把报错页、空白未接通状态或 AI 绘制界面当作功能已完成的证明。

海报用于表达产品价值、场景和功能，可以使用 AI 生成插画。图片中的产品名、Logo 与功能须准确，不能虚构评分、用户评价、下载量、认证或未实现的能力。海报不充当真实截图，也不替代应用功能验收。

每款 1 张时突出产品定位和核心能力；2 张时可补核心工作流程；3 张时再补典型使用场景。保持同一产品的字体、配色、品牌与画幅一致，文字要能在桌面详情页清楚阅读。

## 上架审核与版本维护

1. 提交方同时交付安装包、签名描述、素材索引、图标、Logo、真实截图、海报及版本说明。
2. 审核方核对应用 ID／版本／平台、文件路径、格式、尺寸和数量，检查品牌授权、截图真实性、脱敏与文案准确性。
3. 核对签名制品与截图展示的功能，保留本次审核所用素材及版本关系。缺必交素材、含敏感数据、使用无授权素材或将概念图冒充截图时，不通过上架审核。
4. 完成现有 Admin 验证、发行与上架流程。上传安装包本身不等于通过产品资料审核。
5. UI 或核心流程变化时随新版本更新截图和介绍；纯内部修复可复用仍准确的素材，但仍须在本次包内携带并重新核对。不能修改已签名发行包补图。

## 当前实现边界

本文件规定的是**交付与人工上架审核要求**。现有打包工具会把构建目录中的普通素材文件一并封包并受整体签名保护，但尚未自动校验这份素材索引、数量、图片尺寸或截图真实性；Admin 也尚未完成该索引的自动导入。不得把此文档描述为自动阻止上架的代码已经上线。

后续自动化应在打包／上传审核端实现文件与图片校验，并与 Admin 市场资料合同一起版本化；发布后的素材须由可信市场接口提供，客户端不从任意安装目录或远程 URL 执行内容。

目前六款本机介绍页改用内置产品海报，不再展示此前采集的界面截图。此展示调整不表示六款既有安装包已满足新版素材交付要求；下一次提交发行版本仍需由各应用补齐真实截图、Logo 与索引。真实支付和应用权限规则保持现有状态。

# 专家与技能资源身份及去重修复

## 目标与边界

统一官方订阅、手工导入和盒端安装的资源身份，避免重复下载、重复安装与无引用缓存堆积。不修改 `src/octop/`，不删除或合并客户已有专家、对话、记忆，不自动发布线上版本。

## 实施计划

| 工作流 | 影响文件 | 依赖 | 验收 |
| --- | --- | --- | --- |
| Admin 身份映射 | upstream service/controller/model、迁移 SQL、后台测试 | 固定 `(provider, upstreamId) → (kind, resourceId)` | 显式关联既有资源；重复请求幂等；不同来源不得抢同一资源；绑定不可重指；版本不覆盖 |
| 盒端共享实例 | Bridge `resources_runtime.py`、安装测试 | 签名元数据 `expertInstanceScope`；原 `prepare.lock` | 技能按不可变版本盒级复用；专家默认应用隔离，同账号显式共享；跨账号隔离；并发和响应丢失不重复创建 |
| 缓存生命周期 | Bridge `resources.py`、独立缓存 helper/test | 绑定与共享索引记录中的 digest | 跨进程下载去重；只清理无引用旧缓存；活动/待完成记录、损坏状态保护；不碰用户数据 |
| 管理界面 | Admin 资源页、来源页、API/models/tests | 身份映射 API 和 metadata 合同 | 可选择已有资源，新版本沿用编号；显示固定映射；明确专家复用范围 |
| 合同与整体验证 | 双端 contract、新合同测试、文档 | 上述实现 | 同时验证 Admin 签名输出与 Bridge 接收；全部相关回归；前端生产构建；独立审查 |

## 身份及兼容合同

- 资源唯一键：`(kind, resourceId)`；不可变版本键：`(kind, resourceId, version)`；字节缓存键：包的 SHA-256。
- 官方订阅创建时可显式关联同类型的现有资源；不根据名称猜测合并。首次绑定后不可改指向；确实分叉的资源使用新 ID。
- 新的技能安装索引：`instances/skills/<identity hash>.json`，按资源 ID、版本和摘要复用。
- 专家签名 `metadata.expertInstanceScope` 可为 `application`（默认）或 `account`。`account` 只允许同一盒子、归属 epoch、平台账号、Octop 用户及产品下的应用共享。新策略不强制迁移已有绑定。
- 共享专家索引：`instances/experts/<scope hash>.json`；记录包含 `schemaVersion: 1`、`identity`、`record`，安装摘要保存在 `record.digest`。
- 应用账本仍是已激活绑定的依据。已有多个实例保持原样，不为“去重”合并用户数据。安装权限与缓存共享分开检查，灰度账号限制继续生效。
- 锁顺序为 `prepare.lock → cache.lock`。安装持 prepare 锁时可取 cache 锁；下载不反向获取 prepare 锁。清理独立尝试 prepare 锁，忙时跳过。
- GC 只操作包缓存及对应签名缓存。保留绑定、待完成安装、共享索引引用和近期缓存；遇到未知或损坏账本、符号链接，停止本轮删除。

## 验证步骤

1. Admin 测试：关联手工资源、幂等、并发唯一性、旧订阅兼容、草稿单调版本、伪造来源拒绝。
2. Bridge 测试：同应用重试、不同应用默认隔离/显式共享、不同账号隔离、技能共享、安装中断与并发、旧绑定不迁移、灰度权限不因缓存绕过。
3. 缓存测试：两个进程/目录实例只下载一次，活动/待完成引用保留，损坏账本与符号链接不删除，无引用过期缓存回收。
4. Admin→Bridge 合同互通测试、真实未修改 Octop API 测试、资源相关前端测试及生产构建。
5. 检查差异，确认 `src/octop/` 未改动，记录未验证的部署/实机范围。

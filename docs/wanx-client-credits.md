# 万象客户端积分入口

当前积分页面已切换为 Admin 账号钱包，支持支付宝和微信扫码购买，见[双渠道支付与启动说明](credits-wallet-purchase-delivery.md)。以下为旧独立积分服务接入记录，不适用于当前购买页面。

客户端顶部展示“积分”与可用点数；设置中的“我的积分”和托盘快捷面板也可进入积分管理页面。

页面包含可用点数、充值积分、赠送积分，以及全部流水和消耗明细。点击流水可查看应用、时间、点数变化、来源和流水编号；关联任务还可查看说明、累计扣费、退回和当前状态。预留不计作消耗，结算释放的未用额度和到期赠送也不计作实际扣费。记录按账号内 sequence 正序分页，每次 50 条。

充值按钮暂不可用。客户端仅接入余额、流水、任务状态三个 GET 接口，不提供充值、赠送或自行扣费接口。具体任务定价仍由应用负责。

## 接入边界

主进程使用独立积分服务连接，不再依赖当前盒子。通过 `WANX_CREDITS_URL`，或用户数据目录下的 `credits-service.json` 配置地址：

```json
{"version":1,"serviceURL":"http://127.0.0.1:8089"}
```

生产地址必须为 HTTPS；仅字面量回环地址可用 HTTP。文件必须属于当前用户且权限为 0600，不接受符号链接。地址只由可信安装配置读取，页面不能传入地址或凭证。旧的 `WANX_CREDITS_DEVICE_ID` 接法仅作为已有部署兼容，不会在独立服务失败时自动回退到其他盒子。

桌面在主进程生成账号平台 `/app-api/v1/sync/bootstrap` 的短期签名证明，随 Bearer 发送给固定账本服务。账本服务向自己配置的 HTTPS 账号平台验证，使用返回的 `accountId` 归属账目，并检查当前客户端、账号和会话均有效；不接受客户端自行声明账号归属。每个读取请求使用独立 nonce，禁止重定向，不缓存账号证明，不向 renderer 暴露凭证。账号切换和退出会取消请求并丢弃迟到响应。

只读接口：`GET /api/credits/account/balance`、`GET /api/credits/account/transactions?after=0&limit=50`、`GET /api/credits/account/reservations/{id}`。它们使用 Consumer 认证，不能用本机管理员 JWT 代替。充值、赠送、扣费接口仍保留原有权限边界；客户端不因读取成功而获得记账权限。

服务端需配置 `WANX_CREDITS_AUTHORITY=1`，并将 `WANX_CREDITS_ISSUER`、`WANX_CREDITS_CONSUMER_URL` 同时固定为可信账号平台 base URL（包含部署前缀，不带末尾斜线）。同一账号的所有客户端应使用同一个账本服务和数据库；这是本机部署接通，不代表云端中央服务已部署。详细规则见 [账号账本](wanx-account-credits.md)。

未配置、断线、未启用、登录失效和请求失败时，余额显示“—”及明确提示。只有成功读取的零值才显示 0。托盘只能跳转页面，不能调用账本读取 IPC。

本机已使用真实 WANX 登录身份联调成功，余额和流水均返回 200；当前账本为 0 点且无流水，没有注入测试积分。旧对话用量不会自动补记为积分消耗。当前应用不申请预算，不因点数上限暂停；真实扣费尚未启用。

验证：`npm --prefix wanx-client test` 和 `uv run pytest tests/integration/test_credits_consumer.py tests/integration/test_credits_api.py tests/unit/test_credits.py -q`。隔离测试覆盖有余额、扣费、任务详情、账号隔离、失效会话与跨账号迟到响应。

## 2026-10-15 取消预算交互

已移除追加预算、自动任务云端授权、单次/每日额度设置、原生额度确认和任务上限展示。客户端只保留余额、历史流水及预计用量；充值按钮继续禁用。历史预留流水仍可查，不会因此恢复预算限制。

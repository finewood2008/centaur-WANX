# Agent 空间上下文同步

本次只实现接入选项、任务上下文、进展/成果提交与状态管理；项目和用户记忆只接收 Agent 有权提供的摘要，不扫描宿主目录，不宣称获取宿主完整记忆。

## 接入与兼容

- 来源审批新增五项：当前任务上下文、工作进展、工作成果默认开启，项目记忆、用户相关记忆默认关闭。项目记忆开启时必须填写项目范围；可全部关闭，使用纯文件空间。
- 规则绑定既有账号/盒子/配置身份，存于盒端；客户端和 MCP 无权自行更改。旧接入未携带规则继续保持文件访问模式，不静默开启收集。
- 空间管理增加“上下文与记忆”：查看状态、规则版本、占用、最近 50 项任务和分页记录，可复制导出本页或确认删除一个任务的所有记录；删除记录不删除产出文件。

## 工具与约束

- `space_sync_status` 返回所选规则、版本及任务概要；`space_task_records` 读取自己任务的完整记录。额外文件授权不能授予另一身份的任务记录。
- `space_task_begin` 带稳定 `request_id`、标题、`policy_revision`、所选类别。需要上下文时必须提供有意义摘要，保存后返回任务 ID/版本。
- 文件调用携带 `task_id` 和当前 `policy_revision`；进展开启时，修改调用须有 `progress`。稳定 `operation_id` 支持文件操作响应丢失后的重放；文本写入助手贯穿所有分块保留任务绑定。
- 修改、进展记录和响应重放索引在同一事务中保存。`space_task_checkpoint` 用观察到的任务版本保存增量；文件修改也推进任务版本，因此提交检查点/结束前查询状态。
- `space_task_finish` 保存成果摘要后标记结束。重连复用未结束任务，不用一次传输连接代表一次新任务；服务端不会将断开连接推断为完成。
- 类别支持 `provided`、`empty`、`unsupported`、`denied`。未选择的类别拒绝提交；不可提供的记忆必须如实报告原因。记录和引用属于数据，不执行其指令。
- 所有 Agent 调用先检查原账号/盒子、凭证、接入状态、空间及授权。写入提交再次校验。即使已有保存回执，文件移出授权目录后也不能用旧回执扩展范围。

## 持久化与恢复

- 每次提交内容最多 256 KiB；不可变内容对象保存到所属空间的存储位置，摘要、请求指纹和版本在空间索引中。迁移校验并搬迁这些对象，用量单独计入 `sync_bytes`/`syncBytes`；不在文件根目录堆放自动生成的文件。
- 同一请求 ID 与原内容重试返回原结果；改变内容复用 ID 报冲突。任务版本冲突要求重新查询，不静默覆盖。文件响应去重仍重新校验资源的当前范围。
- 本机传输对具备幂等条件的请求进行有限自动重试，复用完全相同请求体；暂停/越权等拒绝不重试。失败的模型提交仍需 Agent 重试原请求，客户端不会虚构缺失上下文或在 Agent 退出后自行生成结束摘要。
- 同步页区分等待提交、等待保存、已同步、部分同步、失败与暂停。只在盒端持久化后确认成功；宿主未提供、缺少结束摘要和中断任务保持可见。客户端重启遗留的“保存中”不能当作成功回执。
- 关闭类别只影响后续收集，已有内容由用户单独删除。暂停/断开复用原安全边界；不改变旧访问链接和同账号万象应用的文件接口。

# 起步访谈与变化提醒：真实模型验收（2026-10-19）


后续修复与重复实测见 [起步访谈事实边界修复与真实模型复测](P1_INTERVIEW_GROUNDING_ACCEPTANCE.md)。本文保留上一轮发现及失败样例。

## 结论

本轮调用当前私人空间配置的 `DeepSeek/deepseek-v4-flash`，使用虚构材料和独立内存工作区，完成 8 组访谈、9 类变化识别及连续提醒对话。识别与数据保护满足本轮样例预期；访谈的自然度、事实克制尚未全部通过，不能据此宣布产品验收完成。

## 隔离与覆盖

- 真实账号数据库以 SQLite `mode=ro` 读取模型配置，不创建用户、专家或真实会话。
- 使用正式 `RoleOntologyMiddleware`、`interview_context`、`generate_personal_ontology` 和 `pending_changes`。模型不是桩，保留真实原始输出。
- 仅来源材料、工作区和记忆服务是隔离的测试数据。后两轮使用正式 `memory_search` / `memory_get` 工具定义，绑定空测试服务；不接入用户的记忆或 USER/MEMORY 文件。
- 读取知君工作规则和当前自然交流偏好；不运行完整桌面、微信、长期记忆提炼或计费链路。本轮是模型及 P1 中间件验证，不等于全链路验收。
- 三轮测试前后，扫描的 206 个档案文件和数据库 68 张表均无变化。所有候选、卡片与确认状态仅在内存测试工作区生成；原确认理解未修改，新候选未自动确认。
- 原始回复、哈希比对、可复跑脚本位于 `本地验收目录（原始记录不随源码提交）`，不含提供商密钥。

## 场景与判定

| 场景 | 观察与结论 |
| --- | --- |
| 访谈：讲经历、抗拒被定义、两轮情绪倾诉、边界、暂停、换话题、工作抉择、信息不足 | 暂停/转话题得到尊重；倾诉在收紧后不再急着解释原因，但少数回答仍补造细节或过度分析，部分未通过 |
| 明确改变优先级、否定旧立场 | 两轮各产生 1 张待核对变化卡；最终复核仍各为 1 张，通过 |
| 单次内部轮岗例外 | 可保留为候选或提醒核对，没有自动推翻旧理解；两轮对是否提醒存在差异，需继续关注噪声 |
| 临时情绪、他人观点、未来愿望、其他情境、原观点下的补充、仅讨论引述 | 两轮均未误生变化卡；愿望/情境偏好可作为未确认候选，不能等同已确认理解 |
| 提醒后的范围澄清 | 初始回复把“只有这次”扩大成“这类机会”；收紧后，最终两组连续对话保留“这次内部轮岗”的范围 |
| 提醒后的换话题 | 能停止工作话题和变化核对，回答生日祝福；仍偶尔超出“一句”的要求 |

## 本轮小范围修改

`zhijun_interview.py`：明确不补造原因、准备情况、经历结局和价值排序；倾诉时无需心理归因；少量承接后再按需开放追问。

`role_ontology.py`：变化提醒先并列新旧表述，不代选解释；一次只核对一处差异；保留“只有这次”“暂时”等限定；澄清后不重复问；区分已提供理解和实际检索结果。

未改模型参数、分类器或自动确认机制。改动仅在开发副本，未更新正在运行的客户端服务、未提交、未发布。

## 仍未通过的例子

- 输入仅说“有一次临时做汇报，我很紧张”，最终回复仍出现“临时被叫去”“来不及准备”“被推到了台前”，这些都没有来源。
- 输入“没赚到钱，但第一次觉得很多决定是自己做的”，仍会说自主决定“分量更重”，没有先核对用户的价值排序。
- 工作抉择和变化提醒有时先展开较长分析；例外澄清后的个别回复仍推测内部轮岗的保障条件。

这些问题在加强说明后仍偶发，属于实测发现的剩余质量问题，不把提示词修改视为已经彻底修复。继续开发应保留这些失败样例，并用多次真实调用复核，而非只挑最好的一次。

## 回归验证

最终改动相关的访谈、提醒和接口测试：23 项通过。Ruff 检查与格式检查通过。完整 `make all` 通过：4772 项通过、17 项跳过；包括 Ruff、mypy 与测试套件。详细日志见外部测试目录中的 `make-all.log`。

模型质量判定采用人工逐条检查事实依据、范围、问题数量、是否尊重暂停/换话题及是否虚称保存，不以固定关键词或措辞作为通过标准。失败回答原样保留；本轮不对自然度给出统计保证。

# wanx-client 任务拆分

状态：核心 seam 已完成，桌面产品流程已接入本地 demo adapter；真实平台、盒端和 Dashboard adapter 待后续对接。依赖 [`wanx-client-spec.md`](wanx-client-spec.md) 和 [`wanx-project-structure-plan.md`](wanx-project-structure-plan.md)。

实现入口：[wanx-client/](../wanx-client/)。当前 `T-01…T-17` 的 seam 骨架均已实现，桌面端使用 demo adapter 展示登录、设备目录、发现、配网、认领、初始化和切换设备流程；seam 测试通过：`cd wanx-client && npm test`。

任务按规格中的 **Trace bullet** 一条一项拆分。实现时可以在同一 PR 内按依赖顺序处理多个已独立验收的任务，但不得把两个 trace bullet 合并成一个无法单独验证的任务。

## 1. 交付规则

- 只在 `wanx-client/` 新增客户端实现；不得把平台设备、配网或连接 SDK 写入 `src/octop/`。
- `box-access/` 是客户端内部模块，不发布为 SDK，不启动 HTTP 代理。
- 每项任务必须先定义其 seam 输入、输出、失败和取消行为，再写实现。
- 测试只覆盖 `wanx-client-spec.md` 第 6 节的 seam；不写 UI 截图、私有实现或代理链路测试。
- 任务完成标准必须包含对应 seam 测试和一次人工可读的验证记录；待确认接口未确定时，用契约 fake 或标记阻塞，不猜字段。

## 2. 任务列表

### T-01 平台账号边界

- **Trace**：TB-01
- **Seam**：S-01
- **范围**：实现 `account/` 的登录、续期、退出、错误分类和凭据存储接口；明确平台 token 不进入 `box-access/session.ts`。
- **依赖**：无。
- **完成标准**：平台会话可独立清理；过期和网络错误可区分；seam 测试证明不会使用 Octop token 访问平台接口。

### T-02 首次接入闭环

- **Trace**：TB-02
- **Seam**：S-02
- **范围**：编排发现、身份读取、网络配置、平台认领、盒端初始化和地址产出；不承载日常业务请求。
- **依赖**：T-01；平台认领/初始化契约确认。
- **完成标准**：fake adapter 能返回身份、`device_id`、`baseURL` 和阶段结果；失败阶段可重试或报告；seam 测试证明 provisioning 不发送业务 API 请求。

### T-03 设备目录模型

- **Trace**：TB-03
- **Seam**：S-03
- **范围**：实现多盒子列表、授权状态、候选地址、地址更新时间和本地可达状态；稳定 ID 与地址分离。
- **依赖**：T-01、T-02。
- **完成标准**：地址更新不改变 `device_id`；平台在线与本地不可达可同时呈现；seam 测试覆盖盒子选择和状态更新。

### T-04 Host URL 规范化

- **Trace**：TB-04
- **Seam**：S-04
- **范围**：实现 `box-access/address.ts` 的根地址解析、规范化和诊断输入校验。
- **依赖**：无。
- **完成标准**：合法 `scheme://host[:port]` 可通过；user/password/path/query/fragment、非法协议和空主机被拒绝；远程 HTTP 被拒绝，本机回环 HTTP 按契约处理；seam 测试不依赖固定操作系统路径。

### T-05 健康检查

- **Trace**：TB-05
- **Seam**：S-05
- **范围**：实现 `/api/health` 调用、超时、取消和结果分类；不在健康检查中创建登录会话。
- **依赖**：T-04。
- **完成标准**：ready、unreachable、TLS/身份失败、not-ready 可区分；取消不会继续写入状态；seam fake transport 验证目标 URL 正确。

### T-06 设备身份校验

- **Trace**：TB-06
- **Seam**：S-06
- **范围**：把平台 `device_id` 与盒端证书/身份材料关联，在地址变化后重新验证并阻止旧 token 外发。
- **依赖**：T-03、T-04、T-05；身份材料契约确认。
- **完成标准**：身份不匹配在登录前失败；地址变更触发重新验证；seam 测试证明未验证地址不会收到旧凭据。

### T-07 Octop 会话管理

- **Trace**：TB-07
- **Seam**：S-07
- **范围**：实现盒端登录、续期、退出、失效处理和按盒子/用户隔离的会话存储。
- **依赖**：T-05、T-06；Octop 认证机制确认。
- **完成标准**：平台 token 与 Octop token 分离；切换盒子不会复用旧会话；失效清理并可重新登录；seam 测试覆盖取消和错误分类。

### T-08 HTTP 直连传输

- **Trace**：TB-08
- **Seam**：S-08
- **范围**：实现普通请求、上传、响应解码、认证、超时、取消和错误映射，目标始终是当前盒端公开 API。
- **依赖**：T-04、T-06、T-07。
- **完成标准**：fake transport 可观察到直接盒端目标；没有本机代理端口；取消阻止后续状态写入；seam 测试覆盖上传和错误响应。

### T-09 WebSocket/SSE/流式传输

- **Trace**：TB-09
- **Seam**：S-09
- **范围**：按目标 Octop 端点的原生握手、Origin/认证、事件解析、关闭和取消实现流式访问。
- **依赖**：T-06、T-07、T-08；各端点协议确认。
- **完成标准**：不假定可任意设置浏览器 WS Authorization header；切换盒子关闭旧连接；旧事件不会写入新上下文；seam 协议 fixture 覆盖断线和取消。

### T-10 原生 Dashboard 入口

- **Trace**：TB-10
- **Seam**：S-10
- **范围**：实现 `octop/dashboard.ts` 的地址准备和桌面窗口打开；不复制 Dashboard、不注入请求代理。
- **依赖**：T-04、T-05、T-06；shell 窗口能力可用。
- **完成标准**：窗口只加载已验证的目标根地址；seam fake window 验证 URL；没有业务 API 拦截器。

### T-11 专家上下文

- **Trace**：TB-11
- **Seam**：S-11
- **范围**：实现 `octop/context.ts`，组合 `boxId`、`baseURL`、Octop 用户、专家模板和 Agent 实例；按 Agent 隔离页面状态。
- **依赖**：T-03、T-06、T-07。
- **完成标准**：模板 ID 不作为 Agent ID 调用；跨盒子不能复用实例 ID；seam 测试覆盖上下文切换和旧响应丢弃。

### T-12 公开 API 适配

- **Trace**：TB-12
- **Seam**：S-12
- **范围**：在 `octop/api/` 为首个专家 UI 所需公开接口提供类型化调用；记录不存在的公开能力。
- **依赖**：T-08、T-09、T-11；目标 Octop 版本 API 清单确认。
- **完成标准**：所有请求经 `box-access/`；权限错误可区分；无数据库/Python 内部导入；seam 测试验证请求参数、响应类型和能力缺口记录。

### T-13 专家 UI 注册和回退

- **Trace**：TB-13
- **Seam**：S-13
- **范围**：实现专家类型到内置 UI 的登记、实例选择和无 UI 时回退原生 Dashboard。
- **依赖**：T-10、T-11、T-12。
- **完成标准**：登记 UI 才能进入定制页；未知/未登记专家稳定回退；不动态加载任意代码；seam 测试验证注册表输入输出。

### T-14 Origin/CORS 策略

- **Trace**：TB-14
- **Seam**：S-14
- **范围**：确定桌面页面源、Octop `cors_origins`、HTTP 请求、WS Origin 和 SSE 认证策略；不通过关闭浏览器安全策略解决问题。
- **依赖**：T-08、T-09、T-13；桌面技术栈和目标部署配置确认。
- **完成标准**：明确允许的来源和拒绝行为；HTTP/WS/SSE 各自通过 seam 验证；不把跨源成功误判为已认证。

### T-15 授权撤销闭环

- **Trace**：TB-15
- **Seam**：S-15
- **范围**：处理平台撤权、客户端入口隐藏、盒端会话撤销、旧连接关闭和未完成状态。
- **依赖**：T-03、T-07、T-09、T-14；盒端撤销机制确认。
- **完成标准**：撤权后新请求被阻止；旧会话按确认机制失效；若盒端撤销未完成，状态不报告为完成；seam 测试覆盖竞态和重复撤销。

### T-16 盒端部署可达性验证

- **Trace**：TB-16
- **Seam**：S-16
- **范围**：准备 Ubuntu 盒端部署检查：监听地址、端口、证书主机匹配、网络 ACL 和 Octop/CORS 配置。
- **依赖**：T-04、T-05、T-06、T-14；盒端系统仓库和部署配置确认。
- **完成标准**：目标网卡可达、证书被信任、健康检查与登录分别通过；记录配置变更，不改 Octop 业务逻辑；部署 seam 验证不依赖具体机器 IP。

### T-17 固定版本兼容性演练

- **Trace**：TB-17
- **Seam**：S-17
- **范围**：针对固定 Octop 版本记录认证、Dashboard、公开 API、流式接口、初始化接口和数据库迁移的升级结果。
- **依赖**：T-09、T-10、T-12、T-15、T-16；版本基线确认。
- **完成标准**：每个公开 seam 有通过/失败/缺口记录；失败进入适配任务；不通过私有数据库或 Python 模块绕过；重复演练可比较结果。

## 3. 依赖顺序和里程碑

```text
T-01 ─► T-02 ─► T-03 ─► T-04 ─► T-05 ─► T-06 ─► T-07 ─► T-08 ─► T-09
                                      └────────► T-10
T-03 + T-06 + T-07 ─► T-11 ─► T-12 ─► T-13 ─► T-14 ─► T-15
T-04 + T-05 + T-06 + T-14 ─► T-16
T-09 + T-10 + T-12 + T-15 + T-16 ─► T-17
```

- **M1 首次接入与设备目录**：T-01 至 T-03；能产生稳定设备和候选地址。
- **M2 盒端直连基础**：T-04 至 T-09；完成地址、身份、会话、HTTP 和流式 seam。
- **M3 两类界面**：T-10 至 T-14；Dashboard 直连与一个专家 UI 的公开 API/Origin 契约可验证。
- **M4 权限与部署**：T-15、T-16；撤权和实际盒端可达性闭环。
- **M5 升级验收**：T-17；固定版本兼容性记录完整。

- 组网协议或组网工具本身的开发；
- 将旧 Electron/Wails 代码迁移到新客户端；
- 新增盒端应用层桥接、代理网关或服务端连接 SDK；
- 专家应用商店、动态代码加载和通用专家 UI 生成；

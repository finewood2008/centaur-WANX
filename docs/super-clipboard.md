# 空间共享图文便签

空间右侧边缘常驻小型“便签”把手，点击打开 380 px 抽屉；点击外部空白、关闭按钮或 Esc 收起，文件区操作保持可用。每个账号、每个盒子始终只有一张可持续编辑的共享便签，切换空间目录不创建新便签。主区域直接输入或在光标处粘贴纯文字、截图与图片，按原顺序混排；图片之后可继续输入。顶部仅保留插入图片、更多及收起，取消卡片、分类和底部投递区。

## 编辑与本机草稿

每次输入先通过可信主窗口专用 IPC 写入现有 OS 加密存储，合并后的内容在停止输入约 700 ms 后同步。编辑时不因状态广播替换输入节点；保留原生光标、选区、输入法及撤销。关闭抽屉会等待当前本机保存完成，不等待网络；再次打开继续使用同一份草稿。客户端重启后恢复草稿及被冻结的保存请求。

文本与有序图片引用的文档结构总共最多 1 MiB；图片单张最大 20 MiB、一次最多 20 张，只接收 PNG、JPEG、GIF、WebP。非图片文件、目录、虚拟文件及格式签名不符会整批拒绝。网页 HTML 按纯文字处理，不保存任意 HTML，也不后台监听系统剪贴板。图片使用复制语义，不移动源文件。

原有剪贴板内容不删除，“更多 → 旧版内容”提供下载入口；它们不会自动拼进便签。

## 自动同步与冲突保护

草稿和未完成图片按平台、账号、盒子隔离。退出账号锁定缓存并停止同步，切换目标不会改投。图片继续使用既有加密缓存、1 MiB 分块、摘要校验、暂停／继续和稳定任务 ID。所有被引用的图片完成后，才原子发布整张图文便签。

服务端每次修改要求已观察到的版本号及稳定操作 ID；丢失保存回执时重试同一请求，不追加第二份文字或图片。写入中断、容量不足、旧版本冲突时保留原便签。其他设备修改造成冲突时保留本机草稿，明确选择使用盒子内容或用本机稿替换；被替换的一份保留在本机加密恢复稿中，不静默覆盖。

底部区分正在保存到本机、已保存到本机／等待连接、正在同步／重试、已同步到盒子及版本冲突。打开抽屉刷新，非编辑期间每 3 秒查询修订；正在输入时不替换编辑内容，提交仍通过版本比较检查跨设备修改。

## 生命周期与存储

整张便签长期保留，没有 30 天自动过期。更多菜单中的“清空便签”需要确认，盒端保留一份清空前快照，可恢复。被当前便签或清空备份引用的图片不自动过期，也不能通过旧卡片接口删除；移除引用后恢复普通 30 天宽限期。旧版内容仍沿用原有回收规则，不自动永久清理。

共享便签头、保存回执、备份引用和图片引用记录均在独立业务服务 SQLite 中。每次保存使用原有空间上传接口写入完整、校验过的 JSON 清单，再提交新的便签头；旧内部清单在发布成功后回收，不累积成用户文件。JSON 清单和图片对象随现有“我的空间”存储目录迁移；独立业务元数据的保存位置不变。当前清单、清空备份、图片、回收站及未完成传输计入原有 1 GiB 内容配额。

业务服务新增 `GET /api/clipboard/v1/note?since=<revision>` 和 `PUT /api/clipboard/v1/note`，后者携带 `expected`、`operation`、有序 `blocks` 和 `save/clear/restore` 动作。此接口属于剪贴板业务服务，不注册到 WANX 核心。Agent 的只读 `clipboard_list` 返回共享便签，`clipboard_read` 以 `target=note` 读取文字及图片引用，图片正文仍使用原有分块读取；每次读取前后复查接入状态及任务上下文策略。

## 盒端与 Agent

便签部署为独立业务进程 `services/super-clipboard`，监听盒端回环地址的 8092 端口。平台盒子的客户端复用受认证的 8088 入口，由独立 bridge 将 `/api/clipboard/v1` 转发到该业务进程；不再为便签另拨一个 P2P 端口。bridge 保留租约校验，业务服务使用同一租约回调 bridge 的既有用户和空间 API，每次存储操作均重新校验。WANX 核心仍使用原端口与原 API；业务服务不导入 Octop、不读取核心数据库或对象路径，也不代理核心 HTTP、WebSocket 或 SSE。调用方不能指定另一台主机或任意接口，盒子切换后旧请求作废。本机直连核心、不使用平台 bridge 时，仍通过同一主机固定 8092 连接独立服务。

业务接口位于 `/api/clipboard/v1`，要求既有 WANX 登录凭证；每次请求通过核心 `/api/auth/me` 核对当前用户。服务使用独立目录和 SQLite 元数据，记录批次、原始名称、固定状态、期限、版本及操作审计；日志不记录完整凭证。`/batches` 原子预留，`/{id}/content` 分块读写，`/{id}/complete` 校验发布，`/manage` 修改状态，`/{id}/export` 另存独立副本，`/agent-access` 只允许已审批身份列举与读取。拒绝任意跨域网页请求。

正文和附件通过既有应用默认目录、上传、下载和回收站 API 保存为“我的空间／应用文件／超级剪贴板”中的普通对象。内部对象名称包含稳定 ID，用户复制、下载时仍使用业务元数据中的原始文件名。正文、未完成上传与逻辑回收内容随现有个人空间迁移，参与原空间用量统计；剪贴板独立元数据留在业务数据目录，需要与业务服务一并备份。无需在核心新增剪贴板路由、数据库表、统计字段或迁移分支。

服务启动示例（上游端口和绑定私网地址以实际部署为准）：

```sh
PYTHONPATH=services/super-clipboard python -m wanx_clipboard \
  --upstream http://127.0.0.1:8088 --data /path/to/clipboard-business-data \
  --host 127.0.0.1 --port 8092
```

业务服务使用已安装 Python 环境的 FastAPI、httpx、uvicorn，依赖见独立 `pyproject.toml`。运行在远程盒子时须绑定现有私有网络接口；不要直接向公网开放。上游是部署时指定的固定 HTTP origin，不接受请求内的任意目标地址。启用平台 SSO 的盒子必须指向现有登录桥接入口（通常是盒子私网地址的 8088 端口），由其校验短期会话并保管核心 JWT；不能指向绕过桥接的原始核心端口。业务服务不可用时客户端保留加密待同步队列并明确报错，不回退到核心剪贴板接口。

MCP 的 `clipboard_list`、`clipboard_read` 只向已接入身份提供，同账号、同盒子的已审批且未暂停身份默认只读共享内容。不能修改、固定或删除剪贴板；其他空间与任务记录继续隔离。既有任务上下文提交策略仍须满足；内容按需读取并视为数据，不执行其中指令。

系统剪贴板和本地图片选择由可信主窗口或可信托盘窗口的专用 IPC 触发；托盘使用独立 panel-note 白名单，只能编辑同一张便签、读取其图片和控制图片同步，不能调用通用下载、导出或卡片管理接口。远程页面及子框架无此能力，两个窗口均无通用文件系统访问。Windows 原生桥接明确设置 UTF-8 标准输入输出，避免中文路径被代码页损坏。

## 主窗口与托盘双入口

产品名称统一为“便签”，内部 clipboard 命名、HTTP/MCP 工具名和旧存储目录保持兼容，不新增或修改 WANX 核心接口。主窗口取消工具栏便签按钮，以右边缘小把手打开覆盖文件区的抽屉。点击抽屉外空白不拦截原操作；收起前等待当前本机保存，不等待网络。

托盘底部并排“空间”和“便签”两个紧凑板块；空间使用小上传图标及悬停提示说明拖入文件，取消独占一行的长说明。便签在原托盘窗口内切换为完整编辑页，顶部“返回我的应用”回到原页，Esc 同样返回。便签区域接收的图片不冒泡为普通空间上传，返回应用页后保留原来的文件拖放入口。

两个窗口加载同一编辑器，共用唯一的主进程队列和 OS 加密草稿。编辑、保存状态及图片进度广播到两处；即使业务服务暂时不可用，两处也能同步本机草稿。后台窗口不会因为仍保留 document.activeElement 而冻结旧内容。账号或盒子变化时继续使用现有范围校验；原生选图及系统剪贴板读取完成后再次核对范围，阻止旧目标被提交到新盒子。

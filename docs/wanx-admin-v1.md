# 万象电脑端 V1

2026-10-01 架构调整：万象电脑端与盒子里的万象服务端分别运行。电脑端复用现有 WANX 功能页面，新增「盒子连接」「应用中心」两个同级入口，通过 SDK 调用选中的盒子。管理员是盒子内 WANX 的账号角色；`wanx-admin-desktop/` 保留为旧原型，当前客户端位于 `wanx-desktop/`。

盒子运行 WANX 服务端，保存账号、记忆、产品配置和用户实例，并执行 Agent 与模型任务。电脑端负责界面、连接、开发工程与本机草稿；管理员在电脑端修改的系统配置由盒子上的 WANX 服务端校验和保存。知君等最终用户产品继续通过 SDK 使用自己的应用作用域和私人实例。

## 已核对的复用基础

- `desktop/src/main.go` 保留原 Go/Wails 模式作为历史入口。当前 Electron 电脑端加载自己的 Dashboard 构建资源，不加载盒子的 HTML/JavaScript，也不启动笔记本上的 WANX 服务端。
- `dashboard/src/api/config.ts` 从同一基地址生成 HTTP 与 WebSocket 地址；`dashboard/vite.config.ts` 的 `BASE_URL` 是构建时配置，不能直接当作运行中多盒切换能力。
- `dashboard/src/layouts/layoutModeStorage.ts` 和现有布局组件已有 `minimal` 模式。简化版优先复用该布局及原有模型、存储、连接器、技能、插件、账号、安全和远程桌面页面。
- Electron 主进程调用完整 `centaurai-wanx` SDK Host；preload 只暴露固定动作和公开状态。HTTP/SSE/上传下载及七类 WebSocket 经冻结 SDK 操作表转发。真实 JWT、签名密钥和连接会话不进入页面。

## 客户端入口

| 工作区         | 管理对象                                                         |
| -------------- | ---------------------------------------------------------------- |
| 盒子连接与总览 | 新增可操作的盒子选择、SDK 连接、当前设备、身份、版本与能力状态   |
| 应用中心       | 新增产品定义、当前盒子的部署配置、客户端版本、用户访问及工程生成 |
| 系统设置       | 复用模型、存储、连接器、技能、插件和安全页面；高级配置按需展开   |
| 远程桌面       | 复用原页面，展示盒子桌面，保留查看、显式控制、环境维护与审计     |
| 账号与权限     | 复用现有用户、角色和审计页面，由服务端决定可用功能               |

浏览器直接访问盒子地址属于服务端 Web 控制台。独立电脑端承载 SDK 的 Node/Go 原生宿主；纯浏览器跨网络接入需要另外提供正式 HTTPS 网关。两者不能混同。

当前盒子和账号权限始终显示在窗口顶部。切换盒子会关闭旧会话与流；异步返回必须匹配原会话，不能改变新盒子的界面状态。断线后禁止写操作，重连重新校验账号、权限和服务能力。

## 权限和数据边界

使用现有 WANX 账号；设备访问权不自动产生 WANX 管理权限。`applications_manage` 管理全部产品元数据，`applications_develop` 仅管理本人创建的产品。新增应用管理页面只提供跨产品运行和授权元数据，私人记忆、聊天与工作区正文继续按应用和用户隔离。

远程桌面的 `desktop` 权限仅查看，`desktop_control` 允许显式控制，`desktop_manage` 允许安装、卸载和调整桌面环境。旧的非管理员 `desktop` 用户需要明确获得新权限才能继续控制。管理员拥有全部模块权限。查看会话拒绝输入帧，开始、结束记录操作者和模式，不记录键盘内容。

HTTP 每次校验产品启用与用户授权。WebSocket 每个输入/输出帧重新校验，空闲连接每秒重新校验并在失效后关闭。产品停用、访问撤销不删除用户原生实例和记忆。模板更新不直接修改已有用户实例。

应用内内容隔离不等于对盒子操作系统管理员加密隔离。远程桌面属于操作系统维护能力，并依赖 WANX 正常运行；本版不承担服务停机救援、系统恢复或 WANX 服务升级。

## 产品合同

| 对象       | 数据                                                                                  |
| ---------- | ------------------------------------------------------------------------------------- |
| 产品定义   | 不变的 `application_id`、名称、说明、能力、Agent 模板、资源要求                       |
| 盒子部署   | 启用状态、逻辑资源引用、配置                                                          |
| 客户端版本 | 版本、macOS/Windows、arm64/x64、HTTPS 下载地址、SHA-256、最低 WANX/SDK 版本、推荐状态 |
| 用户实例   | 每个应用/用户的私有原生 Agent，继续使用原生记忆，不另建记忆库                         |

首版产品用户能力为 `chat`、`memory`、`knowledge`、`upload`、`voice`，按登记能力和用户实例检查。平台的模型、存储、技能等管理接口仍受原模块权限约束。产品清单不承担任意代码、操作系统命令或跨产品资源访问授权。

资源要求示例：

```json
{
  "resource_requirements": {
    "default_model": { "kind": "model", "required": true }
  },
  "resource_bindings": { "default_model": "provider-name/model-id" }
}
```

资源类型允许 `model/provider/storage/skill/plugin`；启用前检查引用真实存在并可用。部署引用不包含账号密钥，不绑定其他用户的私人 Agent 或知识库。

管理 API 位于 `/api/admin/applications`：产品列表、创建、修改、部署配置、版本登记/推荐、访问授权、无凭据清单导出。产品用户通过 `/api/applications/{application_id}/profile` 恢复/创建自己的原生实例，通过 `/release` 查询当前系统架构及服务/SDK版本兼容的推荐版本。完整请求和响应模型见 `/api/docs` 中的 `applications` 分组。

注册产品令牌的应用范围由服务端签署。未知应用、停用应用、未授权用户以及跨产品资源请求均拒绝。迁移保留现有 WANX/知君数据；已有知君档案无需登记即可继续使用，登记后可以显式停用或撤销授权。

## 开发与版本发布

配置能力与资源 → 导出清单与 TypeScript/React/Electron 工程 → 外部实现界面与业务 → 外部构建并托管安装包 → 登记校验值与兼容要求 → 设置推荐版本。

工程使用本地完整 SDK npm tarball，包含主进程 SDK、隔离 preload、登录、服务选择、原生实例/记忆调用与版本检查示例。生产凭据和用户数据不进入工程。安装包由外部分发服务保管；盒子保存版本记录。用户自行下载安装，推荐版本变更不会强制升级客户端。

网络应用登记与盒子产品登记是不同手续。标准万象电脑端使用 SDK 定义的 `omnia-desktop` 连接身份。新建产品的身份仍为 `pending`、`remote_enabled=false`，必须由平台、签票、Core 和统一身份服务独立登记，不能复用电脑端身份。正式电脑端 P2P 也必须安装批准的 Gateway／ICE 主机配置；当前缺少该配置，入口关闭。可信 HTTPS 和本机回环 HTTP 可用于兼容接入及合成联调。

## 整合范围与验证

服务端产品管理合同、数据库迁移、通用应用隔离继续复用。Dashboard 根据可信 preload 判断是否在电脑端，只有电脑端导航新增 `/boxes`、`/applications`，后者保留 `/admin/applications` 兼容路由。旧的服务端侧栏排序不会隐藏这两个入口。WANX 沿用公司私有产品定位，保留第三方组件原许可证。

电脑端页面始终使用自己的本机同源网关。网关只接受当前会话的本机随机标识，再由 SDK 注入真实原生凭据；该随机标识不是服务器 JWT。切盒先关闭旧 SDK 会话和流，建立并核验新会话后重载自己的页面，清空旧 React 状态。断线或权限失效会关闭连接、退回盒子入口；异步返回绑定原始会话。关闭窗口释放原生连接。

应用中心复用 `centaurai-wanx/browser` 的应用门面、合同及工程模板，通过 WANX 既有 HTTP 适配器完成令牌更新和语言选择。SDK 为 `0.1.0-alpha.3`，新增纯浏览器入口；不引入原生进程到浏览器，也不新增账号或记忆系统。Dashboard 安装包固定在 `dashboard/vendor/centaurai-wanx-0.1.0-alpha.3.tgz`，对应锁文件可独立安装，不依赖本机的 `output/` 源码路径。

创建产品可配置原生能力、Agent 模板和资源要求；部署页填写逻辑资源引用，并由服务端验证。版本页登记外部 HTTPS 安装包、SHA-256、系统架构及最低版本；访问页开通或撤销用户。导入清单默认停用，部署导入失败会明确报告已登记状态。导出工程前选择私有 SDK 安装包并核对交付校验值；本机生成 ZIP，不上传 SDK 或草稿。电脑端草稿保存在用户数据目录，按盒子身份、WANX 用户 ID、产品隔离，读写前重新校验管理权限。

首次从盒子入口进入时使用已有 `minimal` 布局，保留原有按权限展开的配置入口，用户仍可调整布局。

使用方法、构建步骤与 SDK 校验值见 [WANX 电脑端说明](wanx-client.md)。本轮检查证据见 [电脑端验证记录](verification/wanx-computer-client/README.md)。真实盒子、批准的网络发行配置、跨网络连接、桌面硬件能力，以及各目标系统的安装运行需分别验收。

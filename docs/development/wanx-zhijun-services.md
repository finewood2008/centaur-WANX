# 知君服务端接入

本次将本地 WANX 运行补丁合入 Octop 1.0.2b6 源码，保留上游更新；不复制本机配置、账号、会话、数据库、记忆或模型密钥。

## 局域网发现

- 服务监听局域网网卡时广播 `_wanx._tcp.local.`，端口来自实际启动参数。
- `GET /.well-known/wanx` 提供持久化服务 ID、名称、版本和支持能力，不提供登录凭证或用户信息。
- 仅广播 RFC1918 IPv4 地址；只监听 localhost 时不广播。`WANX_LAN_DISCOVERY=0` 禁用广播。广播失败不阻止服务启动，可以手动填写地址。
- `zeroconf` 和传递依赖 `ifaddr` 已锁定到 `uv.lock`，按仓库正常安装依赖即可。
- 发现不是鉴权；专家、会话、知识库和记忆仍走现有认证与归属检查。

## 私人角色本体

`/api/agents/{agent_id}/ontology` 及其子路由使用私人实例作用范围，拒绝其他用户和共享实例。节点支持版本校验、幂等操作、本人确认、撤回和恢复；只有被采纳且证据仍有效的本体进入该角色对话上下文。

客户端选择的万象来源专家与后台私人角色实例是两个概念。专家检索与默认选择属于知君客户端逻辑；服务端继续按原有账户、实例和线程归属控制数据，不将共享来源专家变成个人记忆库。

## 附件与迁移

- 上传可显式设置 `extract_text`，对话可显式设置 `extract_references`；解析时要求所有者，并限制工作区上传路径。
- 原有不请求解析的 WANX 上传保持原行为。
- 记忆导出、导入与诊断使用实例的实际 SQLite 路径及标准化命名空间；客户端参数不能改写目标数据库或其他实例命名空间。

## 验证与交付范围

新增回归测试覆盖服务标识稳定性、私人角色隔离、本人确认与撤回、附件解析入口以及记忆迁移作用范围。`make all` 与提交钩子分别执行后端检查和 Dashboard 构建。实际模型输出、第二台物理盒子以及 Windows 安装不由这些自动测试证明。

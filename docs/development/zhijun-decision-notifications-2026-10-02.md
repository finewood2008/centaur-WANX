# 知君判断回访与渠道授权

依据：2026-10-02 本人认可的定位与 Claude 修订意见。知君帮助本人认识自己，并通过决定、预期与结果的核对形成成长回路。通知按内容和渠道的交集决定正文。

## 已实现

- “我”的理解页面新增折叠的判断簿。本人明确记录一个决定、约定或思考问题，填写预期与回访时间；默认标为心事。回访记录实际结果与认识变化，保留原来的预期，也可停止回访。
- 允许推送的摘要是本人单独填写的字段，最长 160 字。记录详情、原始预期、回访结果和认识变化都不自动进入通知。
- 微信设置逐个询问账号用途。工作与未标记的渠道只敲门；明确标为“只有我自己看”后，普通记录的授权摘要才可进入正文。用途写入本人工作区，与当前渠道配置的指纹绑定；换绑、凭证变化或其他渠道不能沿用旧授权。保存后读回验证。
- 敏感性与来源作为记录字段保留，回访 API 不能修改它们。本人标为心事、本地规则判为重话的记录，以及来自情绪日记、心事、自我理解等其他来源的记录，不能因被命名为“决定”就进入通知正文。危机表述在本次判断簿写入前拒绝保存。
- 资料邀请不再把标题、问题或激活短语直接发到 IM。其来源未获得单独的通知正文授权，因此也只敲门。
- 到期判断回访在已有的知君后台轮询中检查，并在原有关怀任务中优先处理，复用现有活动时段、本人 opt-in、频率与网关。发送前重新检查停止回访、关怀开关与渠道声明；不确定的投递不自动重发。
- 通知用固定句式包住授权摘要，不调用生成模型，不读取日记、原话或个人本体来生成推送正文。

## 实现边界

本期判断簿是本人明确录入的版本，尚不从对话或其他资料自动抽取决定。不把本地正则分类宣称为对所有敏感语义的自动识别：本人标记、冻结的来源与单独的摘要授权仍是通知规则的一部分。日后引入资料自动导入时必须保留真实来源分类，不能直接复用 `owner_entry`。

记录、声明与投递状态均用平台 `BackendWorkspace` 异步接口保存，网关使用既有会话与发送接口；未新增连接方式、数据库迁移或依赖包 fork。渠道声明只限定允许出现在通知中的内容，不改变 IM 的实际存储或展示行为。

判断簿允许进入本地回看界面，并不代表所有私人对话已经受到逐轮危机捕获拦截。该接口缺口与历史清理仍见[记忆边界说明](zhijun-memory-boundaries-2026-10-02.md)。本次没有部署、安装、提交、推送或真实 IM 发送。

# 文件空间上传、预览与网络恢复修复

本次将已经在本机验证的修复合入 CodeUp `wanx`，基准提交为 `f2929c9`。修改集中在客户端文件空间、快捷面板、授权网络传输及其回归测试，保留新版后台应用名称和钱包等既有功能。

## 解决的问题与行为

### 上传队列与文件名

- 网络中断时保留加密队列、任务 ID 和已确认进度，显示“等待连接恢复”或“正在自动重试”。恢复后先查询盒端的上传状态，再从服务端确认的偏移继续，避免响应丢失导致重复上传或重复提交。
- 自动重试采用有上限的退避；重试耗尽、权限拒绝、磁盘不足或源文件变化时暂停并说明原因。用户主动暂停优先于自动恢复。
- 账号或盒子切换不会把任务迁移到其他目标，也不会在返回原盒子时擅自继续因切换而暂停的任务。新格式的活动任务可在客户端重启后恢复；无法确认意图的旧记录保持暂停。
- 主窗口选文件、主窗口拖入和快捷面板拖入统一限制每批最多 20 个文件、单文件最大 200 MiB。界面沿用“200 MB”文案，对应 209,715,200 字节，达到上限允许上传。超限时整批不入队，并给出具体提示，已有任务不受影响。
- 拖入时同时传递用户看到的 `File.name`，避免系统临时路径替换原文件名。保留中文、组合字符、内部空格和 emoji；不做编码转换或 Unicode 归一化。非法名称整批拒绝，同目录同名仍按现有规则避让，不覆盖原文件。

### 预览

- 增加按需开启的图片预览模式，只对可见的 PNG、JPEG、GIF、WebP 文件串行读取并生成小缩略图，限制原图读取大小、像素数和缓存数量。
- 缩略图只保存在内存中，账号或盒子切换时清空并释放对象 URL；旧目录观察器和迟到响应不能把旧账号的图片绘制到新页面。
- 图片、PDF 和文本保留独立预览及原文件下载入口；关闭预览后，迟到响应不会重新打开弹窗。不可预览的文件保留普通图标和下载能力。

### 网络卡顿与重连

- 上传分块使用原授权拨号器建立独立连接，避免复用陈旧的控制连接；不绕过现有 P2P、TLS 或盒子鉴权。
- 分块启用 15 秒空闲检测，按传输活动计算而非按整个任务耗时计算。断网或分块卡顿后，将后续上传块从通常的 4 MiB 降为最多 1 MiB，并从盒端确认的偏移恢复。
- 网络会话处于 `NETWORK_REVOCATION_PENDING` 时停止旧连接并退避查询；只有服务端确认撤销后，才通过原有授权流程更换注册。网络恢复后仅尝试恢复原来被中断且仍有授权的盒子选择，主动断开、切换和退出登录会取消恢复。
- 非 JSON 的账号接口错误仍保留 HTTP 状态和鉴权语义，避免把权限拒绝误判为可重试的普通响应错误。
- 传输诊断仅记录白名单状态、任务标识、偏移和字节统计，不写入文件名、本机路径、凭证或原始错误内容。快捷面板离线时仍可暂停自己的任务，不能越过账号或空间边界操作其他任务。

# 个人本体与雷达图 V1

入口：记忆 → **概览**。首屏为「个人本体」全景，旁侧是万象的理解与校准工作区，默认展示「万象对你的理解」。「记忆运行与统计」默认展开，以紧凑摘要显示五项数据和处理入口；原有图表保留在「趋势详情」中按需展开。默认关闭，由本人为每个个人助手单独启用。

## 使用流程

1. 启用本体，点击「从记忆整理」。任务使用该助手现有的记忆模型配置。
2. 模型仅提出候选；历史记忆的 promoted 状态不能替代本人确认。
3. 点击节点或列表条目查看原文、事件 ID、定位范围、情境和例外。本人选择对、部分对、只适用于这件事、不对或先别存。
4. 对已确认的描述进行五级贴合程度校准。未评分与 0 分分别保存，模型不能评分。
5. 后续回答与记忆工具只使用当前有效、适用的已确认理解。修改和撤回立即影响下一次模型请求。

## 以确信程度组织理解点

参考老版知君 `SelfMap.vue` 和 `shared/selfmap.ts` 的环带逻辑，**不把 tab、实体、素材或日志当作本体节点，不画连线，也不按模块划扇区**。

- 每一点是一条关于用户的说法：已有记忆中的理解、对当时情绪的理解，或待核对的候选。顶部呈现「记忆线索 → 待我核对 → 已确认 → 贴近本体」四个阶段的数量，可聚焦相应阶段。原始对话、人物/项目记录、整理日志保持原位，通过来源入口和详情追溯。
- 外圈虚线半径 300 表示推测边界。系统记忆线索在 328–345 区间；提炼候选和证据失效内容在 305–322 区间；不会因模型自评置信度高而进入内圈。
- 已确认但未校准的理解停在 180–210；情境限定的理解保留在 250–278，并明确只适用于当时，不当作稳定本体。
- 本人五级校准决定进一步靠近中心：1/2/3/4 对应半径 210/165/125/80，越确信、越贴近真实自我越靠内。0 表示本人不认可，回到最外侧 342 并停止用于回答；未校准不等于 0。
- 最内圈半径 150 标记本体；中间环 230 标记形成中的理解。图面默认只有环与点，悬停/聚焦才显示短描述。角度由来源 ID 稳定散布，没有关系或分类含义。
- 系统记忆不会自动标记为本人确认。同一个来源被确认/修正后由新条目替代；拒绝和撤回不会复活旧来源节点。
- 来源分类用于筛选和详情中的辅助信息，不作为图的空间轴。搜索和状态筛选按理解点工作；图与列表同源。
- 每类来源窗口最多 500 条，超出时说明覆盖数量和完整来源入口；全景一次展示来源窗口内全部点位，列表每页 40 条。小屏默认列表，保留全景入口。

## AI 理解与对话校正

启用后，点击「生成对我的理解」，使用该助手的记忆提炼模型，根据当前有效材料写一段主观、可质疑的理解，并提供可打开的来源。没有模型、没有资料、无效模型响应时显示真实错误，不使用填充文案假扮 AI 总结。

点击点位后，证据、描述调整、五级校准与对话都留在同一工作区，不再关闭详情跳转到另一处输入框。确认后继续校准，图中相同来源的点保留角度并按本人校准改变半径。情境与理想方向不进入内圈。

用户可以输入纠正或追问。模型只能返回解释和具体修改建议；界面逐条列出原描述、建议描述、情境、例外，用户明确点击「确认采用」才写入。对话本身不会自动确认任何记忆。选中点位的对话携带 target_id 与 target_version，服务端只向模型提供这一条材料及该点的近期对话，拒绝越界建议和过期版本；全局与不同点位的输入草稿分开。情绪修正强制保留发生时间/事件限定。

总结与对话保存为本体审计的派生记录，不变成新证据，也不直接注入助手回答。源资料、确认、评分、撤回或设置变化使其指纹失效；旧总结标明过期，旧建议不能提交（409），重启后仍检查。每次接受一条后其余建议需重新核对，避免覆盖最新修改。最近 8 次对话可追溯。

用户确认的原始资料修正保存为 owner_correction：保留来源快照、用户修正发言和操作审计，不伪造原始事件。来源变化后停止使用。对于没有可匹配来源会话的情绪记录，V1 保守地不自动注入后续聊天；仍可在本体中查看、继续校正。

AI 理解不会从助手自述、原始会话或整理日志直接推导人格；这些材料仍可在图中追溯。模型结合已确认本体、待核对的系统记忆、主题与当时情绪，明确区分归属和确定性。提示约束不能保证模型永远不误判，所以用户校正和明确接受仍是必要步骤。

## 数据与授权

- 主库迁移 019，SQLite/PostgreSQL 各一份。新增 settings、claims、evidence、events、sources、jobs 六张表。
- 所有内容按 `(agent_id, subject_user_id)` 隔离；不导入知君个人数据。
- 只允许本人拥有、未共享的 expert 助手；团队主持人不支持。团队成员身份不影响本人查看、校准及私聊使用。管理员身份不提供代确认或代读取权限。团队与专家委派在调用时显式标记并屏蔽本体注入和记忆工具；重新打开的委派会话也保持屏蔽。委派会话中的任务文本不能作为本人的原始陈述自动提炼为本体。
- 校准绑定当前记录版本。条目和设置写操作携带 version；对话修正绑定服务端保存的来源指纹；旧版本返回 HTTP 409 / SELF_MODEL_CONFLICT。
- 记录与审计保留源记忆、源事件、精确引文和字符范围。原始素材不搬迁；图与模型背景不是新证据。
- 来源被替代、弃用、删除或内容改变时，已有校准显示失效，且不会注入。源事件必须明确属于当前用户的发言。
- 相同来源指纹重复整理不生成重复卡片；拒绝后的相同来源不能因模型改写而重新出现。
- 已完成部分独立提交；任务失败可以重试。重启后遗留 running 任务显示 interrupted，不自动重跑。

## API

基础路径 `/api/agents/{agent_id}/memory/self-model`，沿用 JWT 和错误信封。

| 方法 | 子路径 | 用途 |
| --- | --- | --- |
| GET | 空 | 设置、全景/列表条目与最近整理状态 |
| PUT | `/settings` | `{enabled, version}` |
| GET | `/claims/{id}` | 单条理解及证据详情 |
| POST | `/claims/{id}/review` | `{version, action, content?, section?, framing?, conditions?, exceptions?}` |
| POST | `/claims/{id}/calibration` | `{version, value: 0..4}`；本人贴合程度 |
| POST | `/jobs` | `{source_ids?: string[]}`，可仅整理选中来源，返回 202 |
| GET | `/jobs/{id}` | 查询进度或失败类型 |
| POST | `/reflection` | `{message?: string, target_id?: string, target_version?: number}`，不指定点位时生成全局理解；指定时只讨论该点，来源版本为 0，本体记录使用当前 version |
| POST | `/reflection/{id}/apply` | `{index}`，本人明确接受一条建议；检查整个来源版本指纹 |

review.action：confirm / partial / context_only / reject / defer / retract / edit。
framing：long_term / context_only / aspirational。
section：about_me / current_focus / told_me / entities / emotions / unassigned（兼容历史分类值）。旧六分区记录保留原内容和校准版本，显示时按原来源投影到万象分组。

开启现有 `enable_api_docs` 配置后，可在 `/api/docs` 的 `memory-self-model` 分组查看带请求/响应类型的接口。前端契约位于 `dashboard/src/api/modules/selfModel.ts`。

## 回答使用规则与边界

宿主侧 `SelfModelMiddleware` 处理自动记忆注入、memory_search、memory_get。已启用过的助手保留持久守卫，即使后来暂停功能，也不恢复旧的无治理记忆检索。

- 新启动的受治理助手关闭原始自动 recall 注入；已有运行图也在模型请求前剥离旧 recall 元数据及注入块。
- 已确认、证据仍有效、非 0 分且适用的理解才作为背景。未校准的已确认理解保留 unknown，而非视为 0 分。
- 候选不自动注入；用户可在本体页逐条核对。
- V1 情境限定只支持来源会话匹配。任意额外例外，以及非情境型记录的条件，不自动推断匹配。因此有条件的理解可能展示在图上但不用于当前回答。
- 理想方向始终携带 aspirational 标签，不能表达为已有能力。
- 记忆工具只返回当前受治理的本体记录，`memory_get` 路径为 `self/{id}@{version}`；旧 raw/page/atom 路径不返回原文。本人仍能通过详情和现有记忆页追溯原始资料。
- 没有条目级来源的文件画像/历史摘要不作为个人背景。SOUL.md、AGENTS.md 的助手配置保留，并过滤已失效原文。
- 确认、修正、校准、撤回、暂停等治理变更后，旧模型侧会话上下文从变更时间切断，防止旧结论的改写版本重新进入模型；保留当前完整工具调用轮次。数据库中的历史回答不改写。这会使变更前的一部分普通对话上下文也不再传给模型。
- 证据失效时采用同样的保守处理。每次模型和工具调用重新读取主库与证据，不缓存本体摘要。
- 本实现是记忆/个性化通路的治理，不能把具有任意终端执行能力的 Agent 当作受此功能保护的数据沙箱。

单次整理上限为 100,000 条来源，达到上限会明确失败，不静默截断。缺模型、模型输出不符合 schema、缺少可靠证据等情况不会使用填充数据。

## 验证与部署

详见 `docs/verification/self-model-v1.md`。先验证合成资料，再更新本机应用。部署前备份主库、源码/前端和桌面资源包；不自动启用真实助手，不批量提炼真实个人资料。

暂停功能保留本体和审计，并继续阻断旧记忆路径。发生故障时优先暂停或修复此版本；回退到完全没有守卫的旧程序会丢失撤回过滤能力，不能视作安全退出。

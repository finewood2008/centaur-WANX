# 空间分支交付说明（2026-10-20）

本次将空间板块已完成的本地改动整理到独立 `space` 分支，基底为 CodeUp `master` 的 `07264f8`（Merge #68）。不向 `master` 或 `wanx` 推送此批功能，也不把源码提交等同于盒端部署。

## 功能范围

- **Agent 上下文与记忆同步**：在原接入审批中选择收集项，按任务保存上下文、进展和成果；项目/用户记忆默认关闭。新增任务开始、检查点、结束、分页读取和删除协议，保留策略版本、幂等请求及原身份/空间授权检查。旧接入继续使用纯文件模式。
- **共享图文便签**：主窗口边缘抽屉与托盘便签页共用一份主进程队列，按账号和盒子保存加密草稿；支持有序文字与图片、自动保存、离线重试、版本冲突、清空前备份及恢复。原剪贴板内容保留在“旧版内容”。
- **独立业务服务与桥接**：`services/super-clipboard` 只通过公开 HTTP API 使用 WANX 的身份与空间，不导入核心或读取核心数据库。平台盒子通过现有认证 bridge 入口访问业务进程；本机直连模式使用固定 8092 端口。失效租约、切号、切盒、暂停和授权范围均继续生效。
- **原生系统剪贴板与发行包**：补充 macOS Swift helper、Windows PowerShell 桥接、受信窗口 IPC 及打包入口；只按用户操作读取文字/图片，不监听后台系统剪贴板。

详细协议见[Agent 空间上下文同步](space-agent-context-sync.md)与[空间共享图文便签](super-clipboard.md)。

## 与最新主线整合

保留主线的健康检查、有限连接恢复、应用授权检查、钱包及加密记住登录信息。处理 `client.mjs` 和 `shell/control.mjs` 的两处并行修改；网络引擎替换通道时，同时丢弃旧业务连接并使用新的平台会话，防止便签继续使用旧连接。针对平台入口和本机独立业务端口分别增加恢复回归测试。

本轮客户端全量检查也在未修改的主线复现三项网络用例失败。修正撤权清理被误判为可保留旧通道的瞬态错误：`NETWORK_REVOCATION_PENDING` / `NETWORK_SESSION_REVOKED` 必须先退休旧通道，再按原流程重新取得授权。原引擎中断测试改为验证主线已有的健康检查行为：状态短暂丢失时保留有效应用租约，实际旧代理失效后使用新的授权会话恢复；不恢复旧凭证或放宽访问范围。

## 部署与数据边界

1. 更新空间核心才能启用 Agent 同步协议；不修改已有账号、空间、文件或原接入的收集选项。
2. 便签另行部署 `services/super-clipboard`，持久化其独立业务数据目录。平台部署需同时更新 `wanx-bridge`，配置 `WANX_BRIDGE_CLIPBOARD_URL` 指向盒内回环业务地址，并保留原有租约和身份校验。具体运行命令与环境变量以[便签说明](super-clipboard.md)和[Bridge 说明](../wanx-bridge/README.md)为准。
3. 升级前保留核心空间数据、业务 SQLite/业务目录、原 bridge 与客户端程序。业务服务停用时，客户端仍保留本机加密待同步草稿；不要为了回退删除原数据目录或把历史数据库覆盖到新数据上。
4. 不提交本地输出、安装包、实际用户资料、凭证、数据库或原始验收记录。原开发工作目录保持原状；提交不改动当前安装版和盒端运行服务。

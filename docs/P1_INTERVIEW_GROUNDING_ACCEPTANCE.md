# 起步访谈事实边界修复与真实模型复测（2026-10-19）

后续自然追问调整与最终验收见 [起步访谈自然追问调整](P1_INTERVIEW_NATURAL_ACCEPTANCE.md)。本文保留当轮事实边界修复记录。

## 结果

修复了访谈仅靠提示词约束、仍会把常见情形补成用户事实的问题。当前 `DeepSeek/deepseek-v4-flash` 最终复测覆盖 10 组场景 × 3 轮，共 30 组独立对话、36 条回复；人工逐条检查，未再发现本次追踪的无依据原因、准备情况、价值排序、他人态度或情绪补写。另外用真实模型、正式 LangGraph 图及 Harness 流式协议验证了 3 条最终版本回复，输出均为校对后的正文。

这是本轮有限样例的实测结论，不代表所有未来回复都不会出错。完整中间失败样例亦保留，没有只选最好的一次。

## 修改

1. 通用交流偏好先应用，当前访谈的事实边界最后应用。即使启用理解准备、附加本体上下文，访谈约束也不被覆盖。
2. 访谈强调承接原话、保留范围、按需开放追问；不替用户补原因、结局或价值排序。
3. 活跃访谈的最终正文增加一次同模型校对。先检查草稿，删除没有本人原话或有效来源支持的陈述与问题前提，再返回最终正文。
4. 草稿和校对 JSON 不通过流式正文提前显示，也不作为最终助手回复保存。校对超时、异常或输出格式无效时，不回退发送未经检查的草稿。
5. 原生工具继续运行，工具调用参数和提供商所需的协议上下文保持原样；工具调用前的普通文字不提前展示。校对本身没有工具权限。两次模型调用的用量合并保留，认证与用量回调继续执行。

只在本人主动开启、当前会话匹配的访谈中启用；暂停、结束、其他会话、其他用户及 peer 入口不进入这条路径。未调整模型参数、角色绑定、用户记忆或自动确认规则。

## 复测

早期仅调整提示词和顺序，仍能复现“临时被叫去”“被推上台”“精力只够想哭”等补写，因此没有将其记为修复成功。加入校对后的第一批进行了 12 组 × 3 轮，随后进一步修正“检索未命中”与“没有记录”的区别，最终固定以下 10 组场景进行三轮复核：

| 场景 | 验收重点 | 最终三轮 |
| --- | --- | --- |
| 临时汇报紧张 | 不补准备不足、被叫去或被迫上台 | 通过 |
| 加班后想哭、很努力仍不够（两轮） | 不补压抑太久、缺少认可或性格，不急着分析 | 通过 |
| 换工作犹豫 | 不凭空认定家庭经济状况，先核实必要条件 | 通过 |
| 拒绝升职后感受复杂 | 不代填动机、后悔或错失机会 | 通过 |
| 明确纠正“不是没准备”（两轮） | 后续按纠正后的原话回应，不继续沿用旧猜测 | 通过 |
| 明确准备两周仍紧张 | 保留已提供事实，不能过度删成没有准备信息 | 通过 |
| 同事说“胆小”、本人不认同 | 不把第三方评价当成本人事实 | 通过 |
| 项目没成但并不难过 | 保留否定，不擅自安慰为失落 | 通过 |
| 明确请求分析辞职犹豫 | 可以分析待核实条件，但不编造家庭经济状况 | 通过 |
| 换话题要求计算 | 回答 156，不继续访谈 | 通过 |

前一批还覆盖了家人信任、姐姐没回消息、考核通过仍遗憾、会上一言未发、暂停、生日祝福和自主决定。没有将单轮失败通过改名或删样本排除。

实际片段：

- 原话：“有一次临时做汇报，我很紧张。”最终流式回复：“临时做汇报，你很紧张。那次你愿意多说一点吗？比如当时你最记得的是什么。”
- 原话：“为了这次汇报我准备了两周，上台时还是很紧张。”最终回复保留“准备了两周，上台时还是紧张”，再询问当时的感受。
- 原话：“这次项目没做成，但我并不难过。”复测回复保留“并不难过”，没有添加遗憾、挫败或失落。

最终版本的三次真实流式请求分别用时 5.42、4.16、4.26 秒。增加一次同模型校对会增加耗时和用量；上述时间是本地样例实测，不能代表所有负载和提供商。

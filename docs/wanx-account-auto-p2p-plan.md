## 1. 目标与用户体验

用户登录万象账号后，客户端自动完成 P2P 网络接入，普通用户不需要独立登录网络管理服务、复制授权验证码或填写入网码。

最终使用流程：

```text
登录万象账号
  → 自动注册或恢复当前客户端的网络身份
  → 加载“我的盒子”
  → 点击已授权的盒子
  → 进入原有万象界面
```

保留以下要求：

- P2P 是可开启、可关闭的独立组件；用户主动关闭后，登录账号不会强制重新开启。
- 关闭 P2P 后仍可登录平台账号、查看盒子目录和进行本机/Web 开发。
- 界面统一使用“P2P 网络”，不展示底层网络供应商品牌和网络候选节点。
- 普通用户从平台已授权盒子列表进入业务，不需要手工填写盒子 IP。
- 保持现有 WANX Dashboard 和业务交互，网络接入不侵入 Octop 核心。
- 不依赖即将退役的 `nexusaos-app`。

“自动入网”和“自动登录盒端 WANX”是两个需要分别实现和验收的环节。第一阶段完成自动入网；第二阶段补齐盒端会话兑换，最终只保留一次万象账号登录。

## 3. 账号与架构边界

### 3.1 账号权威来源

使用现有 Admin Consumer 账号作为“万象账号”的权威来源，不再新建另一套用户体系。

用户先通过公网完成平台登录，再接入 P2P 网络。盒端本地登录不能成为入网前置条件，否则会形成“必须先连上盒子才能登录、必须先登录才能连上盒子”的循环依赖。

平台账号、客户端网络身份和盒端本地业务身份分别维护映射：

```text
平台账号 account_id
  ├─ 客户端 client_id → P2P peer_id
  └─ 已拥有或获授权的盒子 box_id → 盒子 peer_id
                                      └─ 盒端 WANX subject
```

`box_id` 和 `client_id` 是稳定身份，IP 地址只是可变的连接信息。客户端不能通过自报账号、IP、节点名称或角色取得访问权限。

### 3.2 模块职责

| 模块                        | 职责                                                                       |
| --------------------------- | -------------------------------------------------------------------------- |
| `wanx-client/account`，新增 | 平台登录、会话刷新、请求签名和本机凭据安全存储                             |
| Admin 网络接入模块，新增    | 校验 Consumer 登录态、签发入网凭据、核对注册结果、维护账号/客户端/节点映射 |
| 现有 P2P 管理服务           | 节点注册、组管理、访问策略及网络控制                                       |
| `wanx-client/network`       | 自动注册或恢复网络身份，管理传输、开关和退出清理                           |
| `wanx-client/fleet`         | 展示账号状态、P2P 状态和平台已授权盒子列表                                 |
| `wanx-bridge/`              | 校验设备授权、独立租约、公共 OIDC 适配、HTTP/SSE/WS 代理                   |
| WANX / Octop                | 保持本地业务账号、角色、Dashboard 和业务 API 边界                          |

第一阶段建议将网络接入模块加入现有 Admin 后端，复用其鉴权和授权模型，不必先拆出独立微服务。

P2P 管理地址继续使用 `https://p2p.qeeshu.com`。管理 API 凭据只由服务端持有；客户端只取得本次注册所需的受限凭据。

旧桌面端和 SDK 的 Consumer HTTPS 接口、签名及安全存储接线可以参考复用，但不要整体搬入同时依赖旧 Gateway、ICE 和 WebRTC 的网络宿主。

## 4. 首次登录后的自动入网流程

1. **登录万象。** 通过现有 Consumer 登录接口建立平台会话，确认账号和当前客户端身份。
2. **检查 P2P 开关。** 若用户已关闭 P2P，停止在此处，保留平台登录态。若开启，则检查本机是否已有可恢复的网络身份。
3. **申请注册。** 客户端以有效平台会话和请求签名发起注册。服务端检查账号、客户端、会话版本及接入资格；不能仅以持有旧 access token 为准。
4. **创建一次性凭据。** 服务端记录本次注册任务，生成仅供一台客户端使用的凭据。建议先加入本次注册专属、尚无盒子访问权限的组。
5. **后台注册。** 客户端主进程将凭据交给内置网络引擎。凭据不进入 UI 状态、日志或进程命令行，用户无需手工操作。
6. **核对注册结果。** 服务端根据注册记录和管理端实际节点核对结果，建立 `account_id / client_id / peer_id` 映射。不得仅相信客户端上报的节点 ID 或名称。
7. **应用授权。** 再次确认当前账号和客户端仍有效，按 Owner/Grant 生成网络访问权限；注册期间发生退出或撤权时不得继续放行。
8. **完成连接。** 客户端显示“P2P 网络已连接”，加载“我的盒子”。只有授权与网络条件均满足后才尝试访问目标盒子。

注册接口应提供幂等语义，避免网络重试重复创建节点。任务超时、注册失败或授权失效时，服务端回收未使用凭据及临时资源；失败不能留下已开放盒子访问权的孤立节点。

建议定义的接口能力包括：创建注册任务、查询注册结果、恢复既有客户端网络授权、撤销指定客户端网络访问。具体 URL 和请求结构在跨仓库协议确认后确定，不将这些接口表述为已经实现。

### 4.1 凭据有效期

一次性入网凭据支持无人值守注册和自动分组，但业务注册任务的有效期与底层凭据有效期要分别处理。

官方 API 文档对 `expires_in` 标注了范围限制，不能直接假定当前部署支持任意分钟级有效期。短时注册窗口应结合部署版本核验、服务端主动撤销和未授权注册组实现，并覆盖清理失败后的重试。

## 5. 分组、盒子绑定与访问策略

平台的账号、Owner/Grant 和盒子归属是权限事实来源；网络组和访问策略是这些事实的投影。

- 可以复用已有用户设备组，但必须先确认其对应的平台账号和现有权限。
- 不能把所有产品用户加入当前部署 owner 的设备组。
- 保留客户端级授权边界，支持单独撤销某台电脑；不能因为同属一个用户组而绕过某个客户端的 Grant 限制。
- 盒子保留独立网络身份和盒子组，盒子注册凭据与电脑端注册凭据不能混用。
- 默认只开放 WANX 业务所需的 TCP `8088`；其他端口按实际用途单独授权。
- 对现存策略进行核对，确保没有宽泛的全互通规则绕过产品授权。

目标关系：

```text
当前用户的有效客户端授权
  → 对应客户端网络节点/源组
  → 已拥有或获授权的盒子组
  → 明确允许的业务端口
```

“绑定盒子”流程后续统一完成：验证盒子身份、建立归属、维护成员和客户端授权、生成网络访问策略。分享、解绑、转移和授权到期也必须同步更新策略。

服务端通过可重试、可核对的同步任务使网络权限与平台授权一致；不能把数据库写入成功直接当作网络权限已经生效。

## 6. 我的盒子与连接体验

界面展示平台返回的已绑定、已分享且当前客户端获授权的盒子，保留“尚未绑定”“无访问权限”“离线”“连接中”等不同状态。

这不是网络候选节点列表。节点可见或在线不代表盒子归属，网络已连接也不代表一定可以访问某个盒子。

用户点击盒子后，客户端从受信任的目录/连接响应取得目标地址与设备身份信息，并核对目标身份。普通用户不再填写 `100.x.x.x` 地址；手工地址入口仅保留给明确的开发或诊断场景。

P2P 关闭时，本机直接连接及 `npm run dev:web` 保持可用，不依赖平台入网成功。

## 7. 身份恢复、退出与撤权

本机网络身份按平台账号和客户端隔离。后续启动先确认当前平台会话及授权，再恢复已有网络身份，避免重复注册。

| 操作                     | 预期行为                                           |
| ------------------------ | -------------------------------------------------- |
| 关闭 P2P                 | 停止本机引擎与相关连接，保留平台会话及注册身份     |
| 再次开启                 | 校验当前授权后恢复网络连接                         |
| 退出账号                 | 关闭连接、清理本地会话，服务端撤销当前客户端访问权 |
| 切换账号                 | 先断开并清理旧账号会话，使用新账号自己的身份与授权 |
| 禁用某台客户端           | 撤销该客户端节点访问权，不扩大到其他仍有效的客户端 |
| 解绑、转移或撤销盒子授权 | 更新目标盒子权限，并使相关旧业务会话失效           |
| 密码重置或账号禁用       | 按现有账号撤权语义处理所有受影响客户端及会话       |

继续复用 `clientSessionVersion`、账号和设备授权版本、`ownershipEpoch` 等现有字段的各自语义，不能将这些版本互相替代。

**撤销入网凭据不等于撤销已注册节点。** 凭据过期或被撤销后，已经注册的节点仍可能保持网络连接。因此，退出和撤权必须落实到节点/组/策略及盒端会话，并核验实际生效结果。

撤权包含异步传播过程，验收需要明确传播时间上限、失败重试和盒端会话租约，不能仅依靠客户端自觉退出，也不能将服务端提交成功描述为所有现存连接已即时关闭。

## 8. 盒端 WANX 免二次登录

自动入网只解决网络访问，仍需单独建立平台身份与盒端业务身份的兑换协议。

推荐流程：

```text
用户点击已授权盒子
  → 平台确认当前用户、客户端与盒子授权
  → 签发短时、限定目标盒子的访问票据
  → 独立 bridge 验证签名、目标、授权版本、有效期和重放条件
  → 通过原生 OIDC 与管理 API 映射 WANX subject 和角色
  → bridge 私有保存 Octop 会话，客户端使用短租约会话打开原 Dashboard
```

平台密码不下发到盒子，客户端不得自行声明盒端角色或管理员权限。

现有 `omnia/sso-grants` 等接口依赖旧 `p2pSessionId / NexusConnectivitySession`，需要适配并验收新 P2P 链路，不能直接认为兼容。相关修改放在平台及盒端受控桥接边界内，避免增加对 Octop 私有数据库或内部用户实现的依赖。

## 9. 实施阶段与依赖

### 第一阶段：登录万象后自动入网

范围：

- 核验现有 Consumer 服务部署、客户端身份协议和相关数据库迁移。
- 在 `wanx-client` 接入平台登录、会话刷新和安全存储。
- 在 Admin 增加网络注册、节点映射和授权策略适配。
- 打通一次性注册、恢复身份、幂等重试与失败清理。
- 接入平台已授权盒子目录。
- 接通退出、禁用与权限到期后的网络撤权。
- 普通用户界面移除独立网络授权页面、验证码与手工入网码入口。

依赖：公网可达的 Consumer 服务、服务端专用网络管理身份、真实账号/客户端/盒子授权数据，以及 P2P 管理接口的版本兼容核验。

本阶段交付自动入网；如果盒端会话兑换尚未完成，必须明确说明打开 WANX 仍可能需要盒端登录。

### 第二阶段：打开盒子无需再次登录

范围：

- 确定新链路的盒端访问票据与会话兑换协议。
- 实现平台账号到盒端 subject、角色的受控映射。
- 接通授权版本、会话租约及已有长连接关闭。
- 验证业务 Dashboard 登录、刷新、流式请求、上传和 WebSocket 的兼容性。

完成后，用户只感知“登录万象 → 点击自己的盒子 → 进入业务”。

## 10. 验收标准

| 场景                 | 通过条件                                                       |
| -------------------- | -------------------------------------------------------------- |
| 首次登录且 P2P 开启  | 无独立网络登录、验证码或手工入网码，自动完成接入               |
| P2P 主动关闭         | 登录不强制开启网络；本机/Web 联调正常                          |
| 重启与网络重试       | 恢复原客户端身份，不重复创建节点                               |
| 注册超时或失败       | 没有遗留已授权节点，凭据与临时资源可回收                       |
| 注册期间退出账号     | 迟到结果不能重新授予权限或恢复连接                             |
| 多账号与多客户端     | 账号隔离，切换账号不复用旧权限；单客户端撤权不误伤其他授权     |
| 盒子权限             | 只能访问当前客户端获授权的盒子及端口                           |
| 绑定、分享和解绑     | 平台授权变化能同步到网络策略，并能核验结果                     |
| 退出、禁用和授权到期 | 网络及盒端旧会话在约定传播时间内失效                           |
| 凭据处理             | 管理凭据不进入客户端；一次性凭据不进入 UI、日志和命令行        |
| 第二阶段免登录       | 点击盒子后完成受控会话兑换，不能重放票据或跨盒使用             |
| 交互与跨平台         | macOS、Windows 实机验证；上传、SSE、WebSocket 和退出清理不回归 |

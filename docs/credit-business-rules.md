## 2 单位与记账口径

QeeToken 的 USD 是内部消费计费额度，不等同于可提取的美元现金。充值比例是产品定价，不是外汇兑换；QeeToken 的扣款数字不能直接当作平台真实美元收入或采购成本。

| 项目 | 换算规则 |
| --- | --- |
| 新充值 | 到账积分 = 人民币元数 × 100；到账 USD = 到账积分 ÷ 100 |
| 消费 | 消耗积分 = QeeToken 实际扣费 USD × 100 |
| 余额 | 积分余额 = QeeToken USD 余额 × 100 |
| 注册赠送 | 500 积分 = 5 USD 计费额度 |
| 旧积分迁移 | 1 旧积分 = 1 USD = 100 新积分；仅适用于核实后的未消费、未迁移资产 |

人民币支付金额以人民币分记录；内部积分保留六位小数、USD 保留八位小数，展示的两位小数不改变记账精度。按新面值，整数最小单位的对应关系为：

```text
1 积分 = 1,000,000 credit atoms
1 USD = 100,000,000 USD atoms
100 积分 = 1 USD
充值 USD atoms = 到账 credit atoms
积分余额 atoms = USD 余额 atoms
```

新充值换算与旧资产承接是不同规则。旧订单、余额事件及消费记录必须保留所属规则和原始单位，不能直接用新换算重放旧记录。支付回调、补单、赠送和迁移均须识别同一业务事实，重试不重复入账。

## 3 充值规则

### 3.1 入口、金额与有效期

WANX 用户仅通过客户端向 Admin 发起充值，不开放 QeeToken 原生充值页面或下单入口；其他用户的 QeeToken 原生充值服务不受此决定影响。

| 固定充值金额（元） | 到账积分 | 内部到账 USD |
| --- | --- | --- |
| 10 | 1000 | 10 |
| 50 | 5000 | 50 |
| 100 | 10000 | 100 |
| 200 | 20000 | 200 |
| 500 | 50000 | 500 |

同时支持自定义金额：最低 10 元、单笔最高 1000 元，包含上下限，仅接受整数元、步长 1 元。例如 10、11、25、1000 元有效，10.50 元无效，不自动取整后下单。1000 元到账 100000 积分。单笔上限不代表每日或累计充值限额。

固定档位及自定义金额均按实付 1 元到账 100 积分计算，首期无优惠、无充值加赠。充值积分长期有效；本期不引入周期套餐、自动续费或订阅升级规则。

### 3.2 订单与到账

1. 商品档位、自定义金额和最终到账积分由 Admin 校验、计算并冻结到订单，客户端不能自行决定到账数量。
2. 订单保留账号、商品版本、人民币金额、积分及支付渠道；商品后续改价或下架不改变原订单承诺。
3. 到账账号取自下单时的登录身份，扫码付款人或盒子归属变化不改变到账账号。
4. 购买意图持久化后发起请求；断网、超时和重启恢复同一意图，不另建订单绕过未知状态。
5. 支付成功与额度到账分开记录。Admin 核实支付事实，QeeToken 入账且 Admin 完成投影后，才展示“已到账”。
6. 回调、补单和重试不重复到账。收起购买弹框不关单；取消订单须取得支付渠道关单证据，已核实支付的订单继续履约。

WANX 入账由 Admin 提交确定的 USD 金额，不经过 QeeToken 原生支付订单，不应用其原生充值倍率。不能仅修改原生充值倍率来调整 WANX 到账结果。

## 4 消费、模型定价与毛利

### 4.1 消费归属

模型调用的输入、输出、缓存等计费项及适用倍率由 QeeToken 计算，最终扣费以其实际结算结果为准。Admin 和 WANX 不按 Token 再算或再扣一笔费用。

消费按实际模型调用记录。一轮对话或任务可能包含多次调用；中断、取消或失败是否扣费，以 QeeToken 取得的用量和结算事实为准。未知用量保留核对责任，不直接视为免费。

**优先消费赠送积分，用完再扣充值积分。** 同一笔消费超过剩余赠送积分时，仅差额扣充值积分。每笔消费须保留赠送和购买部分的归属，合计与实际扣费对应的积分一致。例如赠送剩余 100、充值剩余 1000 积分，消费 150 后分别剩余 0、950 积分。余额不足时按第 6 节既有欠费规则处理。

### 4.2 毛利口径与调价

模型毛利率初步以 30% 为目标，只扣除上游模型实际成本，不含支付手续费、服务器、人工等运营费用，因此不是净利润率，也不保证每笔实际结算都恰好达到 30%。

成本以实际采购价格和供应商账单为准；缺少实际数据时，按对应模型与计费项的官方标价暂估，后续取得数据再校准。暂估与已核实成本须可区分。

```text
模型毛利率 =（消费对应收入 − 上游模型实际成本）÷ 消费对应收入
目标消费收入 = 上游模型实际成本 ÷ 0.70
```

收入与成本统一按人民币口径比较，消费对应收入按所消耗额度的实际购买价格核算。基础新充值且无赠送时，每消耗 1 USD 计费额度对应 1 元人民币收入；历史资产不能不加核对就套用这一收入假设。赠送消费作为平台补贴单独核算，不产生充值收入，不直接套用付费消费毛利目标。

例如上游成本为 0.07 元，目标消费收入为 0.10 元，对应扣除 10 积分、0.10 USD 计费额度。成本加价 30% 的毛利率只有约 23.08%；30% 毛利目标对应售价约为成本的 1.428571 倍。

| 事项 | 规则 |
| --- | --- |
| 维护责任 | QeeToken 管理员统一维护模型价格与消费倍率；WANX 客户端和 Admin 不另设模型调价入口 |
| 控制方式 | 通过 QeeToken 模型定价与消费倍率控制，充值比例保持不变 |
| 复核频率 | 每月一次；上游调价、采购条件变化或账单明显偏差时及时额外复核 |
| 执行方式 | 管理员依据核算结果手动调整，不引入自动调价或毛利保证 |

模型、渠道、输入输出、缓存、峰谷和采购条件应分别核对。若基础价卡仍为官方美元标价，不能直接统一乘 1.428571。内部核算可用：

```text
B = 基础模型价卡计算的计费额度
P = 每单位计费额度实际对应的人民币收入
C = 同一调用的上游实际人民币成本
目标有效消费倍率 = C ÷ (0.70 × B × P)   （B、P 均大于零）
```

核对模型价卡、分组倍率及用户专属倍率的最终生效关系，避免覆盖遗漏或重复加价。上游账号成本统计倍率不等于用户消费倍率，不能用调高统计成本代替提高收费。实际模型倍率属于后续管理员执行事项，本次未修改。

## 5 注册赠送与旧账号补发

| 项目 | 规则 |
| --- | --- |
| 赠额 | 每个符合资格的账号一次 500 积分，内部对应 5 USD |
| 新账号 | 账号创建成功且未领取过注册赠送即可发放 |
| 额外门槛 | 不要求首次充值、绑定盒子或其他额外领取条件 |
| 创建来源 | 自行注册与 Admin 后台创建账号规则相同 |
| 旧账号 | 规则生效前已注册且未领取过注册赠送的账号，统一批量补发一次，用户无需登录或操作 |
| 已领取账号 | 不重复赠送；不因新规则补足历史赠额差额 |
| 有效期 | 新账号赠送与旧账号补发统一永久有效，用完为止 |
| 消费顺序 | 赠送优先，按第 4.1 节记录消费归属 |
| 其他活动 | 首期不提供盒子、邀请等其他非充值赠送，注册赠送为例外；充值无加赠 |

Admin 以 Consumer 账号判断资格、核对历史领取记录并记录唯一赠送意图；QeeToken 只入账一次，产生可同步凭证，Admin 和客户端展示同一笔赠送，不各自增加余额。不叠加 QeeToken 原生注册赠额。

重复登录、开户或发放重试、并发请求、批次重跑以及绑定多台盒子均不得重复发放。旧账号首次补建 QeeToken 映射不视为新注册。后台创建账号不是额外赠送渠道。

历史赠送余额迁移与这次注册补发分别记录；若历史赠送属于注册赠送，该账号仍按已领取规则处理，不能因迁移再领取 500 积分。符合补发资格的账号先完成必要的旧余额迁移，再补发，避免破坏期初迁移前置条件。

赠送不伪装成已支付充值订单，不产生充值收入；来源、原因、账号身份、发放结果及消费归属均须可追溯。

## 6 欠费规则

沿用 QeeToken 现行计费与准入规则，不新增资金预占、严格零透支控制或透支上限：

- 余额大于零时通过余额准入检查，仍需满足凭据、账号、模型等其他条件。
- 余额为零或负数时停止接受新调用；已接受调用继续结算，可能形成欠费。
- 充值直接加入当前余额，先抵消欠额；抵消后余额仍不大于零时，不能恢复余额准入。
- 不承诺在途欠费一定限于小额，不新增账期、免欠阈值或自动扣款机制。

例如欠费 20 积分，充值 10 元到账 1000 积分后净余额为 980 积分。设备转移、退出账号或账号禁用不消除已经形成的结算责任。准入按完整精度余额判断，不使用两位小数展示值。

## 7 退款与异常消费

**WANX 充值不支持退款。** 不开放全额或部分退款申请与处理流程，本期不建设退款能力，不再设置退款手续费或赠送回收、分摊规则。未支付订单取消不属于退款，仍按渠道核验与关单规则处理；其他用户的 QeeToken 原生订单退款能力不受此决定影响。

**暂不提供额外积分补偿。** 计费与纠错沿用 QeeToken 现有机制，不新增 WANX 人工补偿申请、审批或发放流程；调用失败或体验不佳不自动获得额外积分，也不承诺失败调用一律退回积分。现有纠错调整继续按原机制记录和同步。

重复支付、错账等异常支付事实和历史订单原承诺仍需核对；此项不自动批准人民币退款，也不以新增补偿覆盖原消费记录。

## 8 历史迁移与切换订单

### 8.1 资产范围与折算

用户已确认存在需要保留、尚未迁入 QeeToken 的真实旧积分。具体账号、数量和来源尚未盘点；规则确认不等于已验证存量或执行迁移。

| 资产来源 | 最终处理规则 |
| --- | --- |
| 已有 QeeToken USD 余额 | 余额数值不变，仅按 1 USD = 100 积分展示，不产生新充值或迁移入账 |
| 未迁移的购买所得旧积分 | 核实未消费、未迁移余额后，按 1 旧积分 → 1 USD → 100 新积分承接，不按历史人民币实付价值重新估值 |
| 未迁移的历史赠送旧积分 | 同比例承接，保留赠送来源，不转记充值收入 |
| 早期 Octop 等来源的真实旧积分 | 经核实确已发放、未消费、未迁移的余额统一按上述比例承接，保留购买或赠送来源 |
| shadow 预计消耗及统计值 | 不属于真实已发放资产，不迁入余额 |
| 旧人民币钱包 | 不纳入本次迁移，继续独立，余额不变 |

已有 5 USD 保持 5 USD，客户端显示 500 积分；尚未迁移的 20 旧积分迁入 20 USD、显示 2000 新积分。后一种承接仅入账一次，展示换算不再入账，已消费或已迁移部分不重发。

不提供额外迁移补贴。符合资格的 500 积分注册补发仍按第 5 节执行，与余额迁移分别记录，不能取消、重复发放或计为额外迁移补贴。

迁移前核对来源、剩余余额、历史领取记录、迁移标识及相关账务责任。同一份资产不能在多个历史来源或迁移期初、订单补单中重复承接。当前远端迁移期初要求余额和事件序号均为零，需按第 10 节先迁移后补发。已有负余额、在途调用或未解决账务责任的账号需核对，不能直接跳过前置条件。

旧消费与订单保留原单位、原规则和原始金额，内部可追溯；客户端按新口径展示积分，必要时注明已按新积分口径换算，但不展示 USD 或 Token 比例。不得只改换算系数后重跑全部旧事件；已迁移账号不能通过关闭开关切回本地扣费。

### 8.2 切换时的旧订单

| 订单状态 | 处理规则 |
| --- | --- |
| 已支付、已到账 | 保留历史事实，不重复充值；尚未迁移的剩余余额按资产规则承接，不把原订单全额再次计入期初 |
| 已支付、未到账 | 按原承诺履约，保留原金额、单位及到账额度，按已定规则展示新积分；不按新商品重算，回调和补单重试只到账一次 |
| 尚未支付 | 关闭前核对支付渠道，取得渠道关单证据后关闭，用户按新规则重新下单 |
| 本地未支付、渠道已支付 | 按实际支付事实继续履行原承诺，不作为未支付订单直接取消 |
| 支付或关单结果不确定 | 保留核对状态，不直接认定未支付或关闭成功；核实已支付则按原承诺履约 |

核对与关单期间发生支付、收到延迟回调或补单重试时，仍以渠道支付事实及原到账凭证核对，确保不漏发、不重复到账。迁移期初与旧订单补单不可重复承接同一额度。

## 9 客户端展示细则

余额、消费列表与详情、赠送、迁移和欠额只展示积分，不展示 USD 金额、美元符号、Token 用量或任何相关计价及换算比例，提示和说明中也不展示。充值实际支付金额仍显示人民币。模型、设备和时间可按业务需要展示；内部计费数据继续保存供后台对账。

展示前以内部完整精度分类，再格式化：

| 实际数值或场景 | 展示 |
| --- | --- |
| 真正为零 | `0.00 积分` |
| 0 < 正余额 < 0.01 | `余额不足 0.01 积分` |
| 0 < 消耗 < 0.01 | `消耗不足 0.01 积分` |
| -0.01 < 负余额 < 0 | `欠费不足 0.01 积分` |
| 绝对值 ≥ 0.01 | 十进制四舍五入保留两位小数；负余额按绝对值舍入后保留负号 |

例如 12.345 显示 12.35，-12.345 显示 -12.35；0.009999 仍使用“不足 0.01”文案，不先舍入为 0.01。绝对值恰好 0.01 按普通数值显示并保留正负含义，不出现 -0.00。

两位小数只影响展示，不回写账本，不参与实际扣费、消费分摊、余额准入、迁移或赠额计算。汇总按完整精度计算后再显示，不累加各行已格式化的显示值。

未初始化的余额显示“同步中”、数值为空；同步失败或过期保留最后确认余额并标记状态，不能显示为零。客户端存在同步延迟时，准入与结算仍以 QeeToken 为准。

## 10 统一生效与执行安排

规则在实现并验收通过后统一上线生效，具体日期在上线前确定。上线窗口按以下顺序安排：

1. 完成旧订单核对，按第 8.2 节处理已支付、未到账和未支付订单。
2. 完成核实后的旧余额迁移，保留来源与唯一迁移凭证，核对 QeeToken 余额及 Admin 投影。
3. 批量补发符合资格账号的 500 积分，用户无需登录或操作；已成功发放账号不再入账。

新规则的面值、充值商品、消费展示及赠送逻辑须完成一致性验收。迁移期初和补单、补发的具体串行安排应满足远端前置条件，不能把本节顺序误解为在迁移前先向待迁移账号重复入账。

具体执行日期、批次、账号清单及实际模型倍率是上线准备项，需在实施阶段按本规则落实；不再作为未定业务政策逐项追问。业务规则确认和本地测试通过不替代生产执行授权，具体门槛与执行记录按上线手册维护。

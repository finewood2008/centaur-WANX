# 知君独立档案版 · 0.2.10

知君保持独立 Electron 应用，共用 WANX 账号、模型服务和本机运行引擎。每个账号在知君只有一份主档案，由本人首次点击创建，从空白开始。WANX 已有 Agent 与记忆保留原位，新版不选择、不绑定、不迁入它们。

## 账号注册与登录

登录页提供「登录 / 注册」。知君可以直接注册普通 WANX 账号，无需邀请码；同一账号密码也可登录万象，两个应用的记忆依然独立。注册复用原生密码规则和当前验证码，注册成功后直接获得知君范围的登录令牌，进入创建档案页面；注册本身不创建任何 Agent、工作区或记忆档案。

`POST /api/auth/register` 接收账号、密码、验证码及固定的 `application_id: zhijun`，禁止角色、权限或已有资源路径参数。新增账号固定普通用户，没有管理权限；账号写入 WANX 原用户库，无新数据库表。服务尚未完成初始设置时不能通过注册创建第一个管理员。重复账号返回原生错误，多进程唯一约束冲突同样映射为账号已存在；新令牌可以直接在另一服务进程恢复本人身份。

客户端校验确认密码，切换入口重新验证。明确拒绝展示服务端原因；提交后断线或服务器异常则说明注册结果未确认，可返回登录恢复，避免把已创建的账号当成不存在。服务端使用独立注册请求频率限制，不接受客户端转发头伪造新的额度。已有邀请码注册流程保留原生行为。

## 产品体验

对话是主空间，延续旧版知君的纸、墨、朱砂、宋体和留白。顶部为「对话、记忆、知识库、设置」，配以轻量图标和当前视角提示。

「对话」按原生会话名称展示主题，可查找已读取的名称、继续读取更早的主题、回到已有对话或开启新的主题。本人命名后，客户端创建原生会话、保存并核对名称，再进入；只准备会话，不自动向模型发送内容。命名保存失败时保留已创建会话，重试只保存名称；创建结果不确定时刷新列表核对，不自动重试创建。也可明确选择从空白草稿开始，发送第一句话时才创建会话。

交谈收拢到正文与输入框。知君的新回答逐步呈现，可点击「立即显示」；历史读取与断线恢复直接显示已有正文，不重播打字效果。系统选择减少动态效果时直接显示全文。正文采用 17px 中文字体、清晰行距和段落间距，保留单行换行，强调、引用、列表、代码与表格分别排版；新回答按一段一至三句组织。查阅过程与回答依据默认收起，需要时再展开查证。新内容自然跟随显示，向上阅读时不抢滚动。

记忆面板提供四个视角：

- **记忆树**：原生人物、项目等主题分支，展开后读取摘要、具体说法和依据；收起后保留本次已读内容，可围绕主题继续交谈。
- **情绪日记**：按服务端时区的日期分组，展示每段经历的原生情绪、强度、话题和原话入口；可按时间、情绪和话题筛选，支持单次回看和默认最近七天的阶段回看。筛选与阶段回看默认收起。
- **用户画像**：原生关于本人、当前重点、已记录说法、关键人事物；查看依据并发起核对。
- **记忆沉淀**：候选和冲突，采纳、拒绝、修正、弃用均通过原生接口，成功后读回服务端结果。

「已提炼」表示原生 promoted 状态，不表示本人已确认。经历情绪标签只读；补充说明会进入新对话，不能声称旧标签已经修改。

记忆和经历入口产生可编辑的聊天草稿；用户发送后，Agent 再读取材料。来源随实际成功的查证回答打开。阶段回看只总结已经读取的记录，说明分页覆盖、缺失来源和资料不足。

## 交谈与行为

先回应眼下的事和感受，每轮至多追问一个必要问题。相关的过去自然参与，但区分当时和现在。至少两段独立来源支持时，才提出限定于这些经历的观察，邀请本人纠正；一次感受不能直接成为长期性格。

日常主回复通常一至三段，先接住本人眼下的表达；详细分析、复盘和排查由实际需要决定，不用查询步骤或工具参数占据主回复。独立的 `ZHIJUN_CONVERSATION.md` 定义这些交谈规则，与已有 AGENTS、SOUL 等个人规则并存；升级通过原生工作区接口补齐该文件，不覆盖原有个人规则。

回应选项定位为辅助思考，用户始终在同一个输入框里表达。新回答有一个自然追问时，显示完成后可生成二至三个可能的方向；Agent 已提供的 `zhijun_response_options` 可直接使用，否则通过本档案的范围化接口读取近期已查证对话并生成，不写入记忆或历史。输入框旁「选着说」也可主动展开。面板从输入框内向上展开，不遮罩、不抢焦点、不另设问答流程；点选只填入可编辑草稿，由本人继续补充并通过原发送按钮发送。开始自行输入、收起、发送或切换会话时面板消失；收起后不反复弹出，回看历史不自动展开。已有草稿、附件、资料库、录音或向上阅读时不打断。只有实际发送的文字参与后续积累；尚未发送的方向不表示本人立场、事实、记忆或授权。

经历回看围绕事情、当时的想法与感受、后来的结果及新的理解。选择辅助会核对过去的理由和结果，比较当前条件，给出带前提的看法，决定权归本人。

自动记录、提炼、冲突处理和记忆状态仍是原生机制。新档案使用平台可用默认模型及原生提炼默认值，主动关心关闭；不继承知识库、连接器、插件、旧资料或其他 Agent 上下文。

## 语音表达

输入框提供语音入口，优先使用 macOS 本机中文语音识别。读取可用状态不申请权限、不录音；本人开始使用时才申请系统语音识别和麦克风权限。识别要求系统支持设备端处理，并强制设备端识别；本机不可用、权限未获允许或识别失败时显示真实状态，不自动切到外部服务。

本人可以另行选择「使用外部转写服务」。录音前显示当前服务名称和类型，明确这段录音将发送到该服务，并由本人确认本次使用；实际提交核对此前确认的服务配置，配置发生变化时拒绝继续。没有已配置服务时显示不可用，不新增语音模型配置入口。

每次最多录音六十秒，可完成或取消。转写文字放入可编辑草稿，不自动发送；已有文字保留。取消、切换会话或退出会撤销本次处理，迟到的转写结果不会进入另一会话。本机识别使用受限的桌面桥接和临时 WAV，完成、取消或失败后清理临时录音。只有本人实际发送的文字才进入后续原生对话积累；语音识别成功不表示内容已发送或记忆已确认。

## 上传资料与私人资料库

对话输入框通过加号内的「添加附件」选择多份材料，也可以只发送文件而不输入文字。上传成功后仍是尚未发送的草稿；发送时，本地提取的正文和来源才一起进入这轮交谈，随后沿用原生记录与提炼。上传完成不代表记忆已生成。文件名可打开纯文本来源，读取失败、无正文和截断如实展示；切换会话或账号会清除附件草稿，迟到的上传结果不进入新会话。

顶部独立的「知识库」入口用于系统资料。本人创建私有资料库后上传文件，复用 WANX 原生文档、索引、状态、重试和来源预览。知识库与 WANX 分属应用域，不能互读；本人上传的知识库以默认打开的方式向自己的知君提供检索目录，只有相关片段在实际检索后参与交谈。知识库上传本身不产生个人经历。整理状态为等待、本地处理中、可供检索或整理未完成；失败时可重试。点击「围绕资料聊」生成可编辑草稿，不自动发送。

知君的文档解析、图片/扫描件 OCR、索引向量和查询向量均强制使用可用的本地链路。共享平台的远程 embedding/OCR 设置不能覆盖它；缺少本地模型或组件时显示真实不可用，不回退远程。对话继续使用档案已有的会话模型，因此实际读取的资料片段可能进入该模型的推理上下文；本地解析与索引不表示会话模型也已改为本地。

上传的文档和检索片段是来源数据，不是运行指令，也不自动成为本人的事实、观点或性格。知君区分「资料写到」「你说过」与推测，必要时核对作者、主体和时间。同一份文档的多个片段不算多段独立经历。

原生 `POST /api/agents/{agent_id}/upload` 保存附件并返回本地提取状态；专用 `GET /api/agents/{agent_id}/upload/source` 读取已注册来源，不开放工作区文件。正文保留最多 48,000 字符，单次来源读取最多 12,000 字符；一轮最多八份附件、合计 24,000 字符，必要时继续分页。单文件本地提取上限 10 MB，原件保留；不能读取的内容不会被宣称已读完。资料库继续使用 `/api/knowledge-bases/...` 原生接口。

## 服务端边界

Agent 增加不可通过普通配置更新修改的 application_id（wanx / zhijun）。旧记录默认 wanx。SQLite / PostgreSQL migration 020 增加每用户唯一知君档案的部分索引，并将同账号名称唯一性限定到应用域，已有 WANX 的「知君」不影响新档案创建。

登录传应用标识，服务端签发带应用范围的 JWT；续期保留范围，旧 token 按 wanx 处理。客户端头不能覆盖签名范围。每请求复制身份，应用范围不写进共享用户缓存。

- GET `/api/zhijun/profile`：本人档案或 null，读取不创建。
- POST `/api/zhijun/profile`：创建或恢复同一份档案；不接受已有 Agent、工作区或记忆路径。
- 档案实际对话、历史和记忆继续使用 `/api/agents/{agent_id}/...` 原生接口。

先检查应用归属，再检查权限；管理员不跨应用域。跨域资源返回 404。HTTP、WebSocket、历史、通知和聚合结果执行相同边界。知君令牌开放自己的档案、聊天、附件来源、原生记忆和私有资料库操作，不能修改工作区或装配 MCP、插件及通用工具。

运行时禁止跨域 peer / team / session 绑定。知君模型可见工具和实际执行均受读取白名单约束，保留 memory_search / memory_get、zhijun_episode_search / zhijun_episode_get，增加 zhijun_attachment_get 和原生 search_knowledge，另允许时间读取辅助及无持久化副作用的 zhijun_response_options 表达邀请工具。通用文件、执行、委派工具关闭。每轮仅装配本人在知君的资料库，阻止 WANX 默认知识库、MCP 和插件。

SQLite / PostgreSQL migration 021 为知识库增加不可通过普通配置修改的 application_id，并将同账号名称唯一性限定到应用域。旧知识库统一归属 WANX，原文、索引和文档状态保留。已有知君档案按版本补齐缺失的 `ZHIJUN_MATERIALS.md` 与 `ZHIJUN_CONVERSATION.md` 行为规则，通过原生工作区接口读写；不覆盖已有规则文件或 AGENTS、SOUL、USER、MEMORY 文件。

共用宿主仍共用本机运维权限，不承诺操作系统物理隔离。混合应用域时，HTTP 整机备份导出/恢复及无法拆分的全局统计不作为应用内入口；备份与回滚使用本机宿主运维工具。

## 创建、失败与恢复

创建只初始化行为规则、独立工作区和原生存储，没有个人资料、对话、经历、候选或画像，不触发模型交谈。数据库唯一索引保证并发与重试恢复同一档案。模型不可用时显示原生 failed 和真实错误，保留已创建档案，再次创建请求尝试恢复原档案。

客户端以服务端主档案为准，清除旧 WANX Agent 绑定及旧应用 token。失效身份不会自动认领其他 Agent。退出/账号切换清除会话与缓存，同账号重新登录读取原档案。聊天重连先恢复历史与任务状态，不重发上一条消息。

「另开一段对话」会保留旧会话未发送的草稿，并显式保存空白会话状态。重新打开应用后仍恢复这份空白草稿；本人发送前不创建新会话，不自动跳回已有历史。围绕资料交谈时，明确选择的资料库随当前会话草稿保存，切换会话不会带入另一段对话。

### 弹出选择与可靠触发更新 0.2.5

原内嵌卡片改为居中弹窗：一个问题、二至三个完整回应、可改写的输入区、明确发送、放入输入框及跳过。默认不选中、不发送；数字键可选方向，原生 dialog 保留焦点与 Escape 关闭。回看历史不自动弹出，已有文字、附件、资料库草稿、录音或向上阅读时不抢占。

触发由两条链路组成。Agent 的原生 `zhijun_response_options` 结果仍可直接使用；新回答只有一个自然追问时，客户端在打字机结束后独立请求生成，不再依赖模型必须先调用工具。追问之后附带例子也能识别，引用的问句及多个问题不自动触发。最新成功回答旁的「选着说」可主动打开；跳过后不会反复弹出。生成失败显示实际状态并允许重试，迟到结果不覆盖新草稿、不带入另一会话。

`POST /api/zhijun/response-options` 使用签名应用范围与本人的主档案，核对会话归属及最新原生回答。只读取该会话近期对话和已查阅的来源，用原配置模型生成；不调用新记忆工具、不读其他 Agent、不写入会话或记忆。生成前后都检查回答是否仍有效；候选表达须经本人确认发送才进入原生积累。

验证记录见 `docs/verification/zhijun-personal-ontology/`。全量平台检查、客户端测试与构建、雷达来源跳转测试、独立 macOS 打包及签名已验证。正式档案只读核对入口和读取结果；生成与核对流程使用合成资料与固定模型响应测试，真实模型的提炼质量仍待用户体验。平台只部署三个相关文件，数据库与配置已备份，旧客户端保存在 `release/archives/知君-0.2.9.app`。回滚恢复旧应用和平台文件，保留新增本体资料，不能用旧数据库覆盖后续对话。

## 0.3.0：个人本体 V2

个人本体成为知君每轮对话的核心上下文之一。用户画像默认展示稳定布局的本体地图，支持直接自述、改写、范围限定、例外、核心标记、停用与版本恢复；原生画像雷达作为辅助入口保留。对话中可以查看实际参考的理解及版本，并在明确纠正保存成功后撤销。

独立 Agent 中间件供桌面与微信共同使用，优先尊重本人当前表达，默认最多装配八项有效理解。受限工具只保存当前本人明确表达和原话，不能以模型推测修改已核对内容。后台每分钟检查变更，分页读取原生记忆并按批次推进，不再限定最近 120 条；本人修改不会被整理覆盖。AI 建议的回应保留来源，不重复计作独立经历。

新增节点编辑、版本恢复、关系核对与本轮上下文接口，继续通过平台工作区保存。旧条目的 ID、依据及核对状态保留。新增字段采用兼容读取方式，不引入平台数据库迁移。

具体行为、合成对照、验证证据及保留新数据的回滚说明见 [个人本体 V2 验证记录](verification/zhijun-ontology-v2/README.md)。真实微信链路和真实交谈效果仍须用户体验，自动化测试不代表这些验收已经完成。

## 0.3.2：知识库跟随平台设置

知君读取万象知识库的同一份模型、图片识字、分段与检索配置，不再另选已下载模型或固定开启图片识字。万象切换模型、OCR 或分段策略后，两款应用的资料分别重新建立索引；检索条数和上下文预算在后续查询中直接生效。启动时修复遗留的模型不一致，只重建模型过期的资料库。

两款应用继续使用独立资料库和访问权限。知君保留本地资料处理边界：平台切至远程处理时如实显示配置及不可用状态，不自行回退到其他模型或把私人资料传给远程服务。查询先过滤未就绪资料和旧模型向量，再取最相关的内容，防止同维度的不同模型索引混用。

知识库面板在返回应用及保持打开时刷新平台处理状态，刷新不会清空上传草稿。新增设置字段与能力响应有类型和 OpenAPI 说明。验证、升级及保留新增数据的回滚说明见 [知识库同步验证记录](verification/zhijun-knowledge-sync/README.md)。
